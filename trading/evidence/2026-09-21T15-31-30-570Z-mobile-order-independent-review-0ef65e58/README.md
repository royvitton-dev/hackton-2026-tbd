원본 DOM·API JSON·JPG를 대조한 결과, **user-03의 첫 매수 체결, 별도 두 번째 매수 취소, 3개 durable 요청 결과 및 새로고침 후 요청 복원**을 확인했다. 잔고·예약 산술에 불일치는 없었다. 첫 주문이 계속 미체결일 것이라는 가정은 실제로 성립하지 않았으며, 새로고침 후 첫 요청 탭 선택도 성공 증거로 취급하지 않는다.

이 검토는 기존 파일 읽기, 원본 이미지 4개 직접 열람, 오프라인 산술 검산만 수행했다. 새 브라우저·API·주문·프로세스·서비스·빌드·Git 작업이나 운영 소스 수정은 하지 않았다.

- 첫 체결: `1000000 − (1×1) = 999999 P`, `1000 + 1 = 1001 h`. 두 번째 접수: `999999 − 1 = 999998 available P`, `1 reserved P`. 취소: `999998 + 1 = 999999 available P`, 예약 0. 취소는 추가 체결을 만들지 않았다. 최종 user-03의 누적 주문은 2개, 체결은 1개다.
- 세 API 스냅샷에서 15계정의 `available + reserved`를 독립 합산한 총량은 모두 **15000000 P / 15000 h**다. 봇들이 계속 거래 중이므로 bot-05의 전체 전후 잔고 차이를 이 체결 하나로 설명하지 않았다.

`reload-requests-dom.json` (**15:26:19.500Z**)과 대응 AX는 요청 결과 탭의 `[pressed]`, 세 요청 결과의 명령 순번, **서로 다른 UUID 3개**를 모두 보여 준다. `codes` 배열에는 취소 카드가 별도 최신 결과에도 표시되어 4개 원소가 있지만 고유 UUID는 정확히 3개다. 따라서 이 마지막 자료를 새로고침 후 복원 확인 근거로 사용한다.
