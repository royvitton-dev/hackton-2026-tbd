# §5·§6·§11 거래/코어 성능 추적 감사

기준: 2026-09-21T12:37:46.7587727Z · `main` HEAD `24fcd160d0a7f70ce2a918018afe6831e4021662`. 담당: `/root/matching_core`. 원명세·현재 소스·테스트 본문·기존 실행 원본을 읽고 작성했다. 새 build/test/load/service/Git 변경은 하지 않았다. 기계 판독 기록과 파일 SHA-256은 [audit.json](audit.json)에 있다.

**90개 요구/시나리오 행: proven 84, incomplete 2, unverified 2, failed 1, optional-not-implemented 1.** 이 숫자는 실행한 테스트 수나 전체 목표의 완료율이 아니다. proven은 인용한 유한 입력·실행 버전의 증거가 있다는 뜻이다.

- **zero allocation 미달:** execute당 14.3323667회(120,000명령에 alloc 1,719,875 + realloc 9). 모든 after 원본이 같다. 목표를 만족한 것으로 취급할 수 없다.
- **새 동일 요청의 처리 중 중복 실험 공백:** API의 12회 동시 replay는 최초 요청의 ACK를 기다린 뒤 수행한다. single writer의 dedup 구조는 확인했지만 최초 처리 중 겹치는 새 동일키 시나리오의 직접 실행 증거는 찾지 못했다. 부모 작업에 즉시 전달했다.
- Core의 mutex/I/O 부재와 durable writer의 blocking sync/recv/checkpoint를 분리해야 한다. 초기 Vec·scratch·status 재사용은 있으나 전체 저장소/이벤트 payload pool은 없다. 채널·서비스 전체 lock-free 진행보장도 검증하지 않았고 문서도 주장하지 않는다.
- A의 처리량·p99 목표는 인용한 짧은 로컬 마이크로벤치에서 통과했다. 3쌍 비교는 할당 호출 감소를 입증하지만 속도 향상이나 성능 회귀 부재는 입증하지 못했다.

범위는 §5·§6의 명시 bullet, §11 거래 시나리오와 A 관련 방법/보고 및 관련 동시성·복구 교차검증이다. 원래 도메인 조사 과정, UI 이벤트 누락/재연결 acceptance(§11 line325), B/C/D 목표 수치, §7 전체 내구성 감사, 배포·장기 관찰·전체완료 판정은 부모 감사 범위다. 이 제외가 해당 기능 실패를 뜻하지 않는다.

## 원본에서 다시 확인한 값

- Release/debug 각각 core rules 19 + oracle 1 통과; tracked legacy JSON 호환성 2 통과. 테스트 본문의 정확값·full Core 비교와 실제 `test result: ok`를 함께 확인했다.
- Storage release는 7 unit fault + 13 recovery 통과. 실제 child kill 후 복구된 저널 prefix와 정상 Core의 **전체** JSON을 비교하는 본문을 읽었다. 공개 snapshot의 200 terminal orders/1,000 trades 제한을 full-state 검증으로 착각하지 않았다.

## 상태 해석과 후속 범위

failed는 명시 목표의 실측 미달(무할당), incomplete는 넓은 성능 구조 목표의 부분 이행, unverified는 직접 실험 또는 진행보장 증거 부재, optional-not-implemented는 선택 정정 기능을 뜻한다. 이 감사에서 새로운 실행으로 공백을 채우지 않았다. OS/전원 장애, 모든 스케줄 interleaving, allocator OOM, 1M/2M 전체 용량 포화를 검증한 것으로 확대하지 않는다. 6시간 관찰 완료 여부도 이 문서의 판정 범위가 아니다.
