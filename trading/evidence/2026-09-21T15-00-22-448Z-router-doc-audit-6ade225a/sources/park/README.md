# TBD Wonder Park

여러 프로젝트를 하나의 3D 미니어처 테마파크로 연결하는 로컬 홈페이지입니다.

## 실행

저장소 최상위 폴더에서 Node.js 22.12 이상으로 실행합니다. 처음에는 [통합 서버의 의존성 설치 절차](ROUTER.md)를 모두 마친 뒤 아래 명령을 실행하세요. 루트의 `npm ci`만으로는 `map` 등 하위 앱의 의존성이 설치되지 않습니다.

```sh
npm run park:dev
```

지도에서 `@fontsource-variable/dm-sans` 또는 `@fontsource-variable/noto-sans-kr` import 오류가 나면 루트에서 `npm --prefix map ci`로 지도의 lockfile에 지정된 의존성을 설치한 뒤 화면을 새로고침하세요.

- 홈페이지: <http://localhost:5190>
- HTML 품질 보고서: <http://localhost:5190/reports/>
- 다른 포트: `PARK_PORT=5195 npm run park:dev`
- 프로덕션: `npm run park:build` 후 `npm run park:preview`

통합 서버는 localhost의 한 포트에서 모든 웹 화면을 경로로 제공합니다. `/park/`, `/map/`, `/dopamin/`, `/pinball/`, `/movie/`, `/webpage/`, `/battery_health/`, `/trading/`, `/vehicle/`로 바로 접근하거나 `/projects/`에서 선택합니다. 어트랙션 입장도 같은 주소의 경로로 연결합니다.

개발 모드는 Vite 미들웨어와 Next.js를 같은 HTTP 서버에 연결하고, 배포 모드는 통합 빌드 파일과 Next.js를 제공합니다. 영상은 HTTP Range를 지원합니다. `/voice/`는 macOS 네이티브 CLI 안내입니다. 거래소 엔진은 `TRADING_ENGINE_URL`로 지정하며 `/trading/backend/`를 통해 HTTP와 WebSocket을 전달합니다. [거래소 최초 준비](../trading/README.md) 후 기본 로컬 엔진은 파크 시작·거래소 입장 시 엔진·12개 봇·독립 UI를 자동 준비하고, 정상 실행 중이면 재사용합니다. 외부 엔진이나 별도로 지정한 다른 포트는 자동 실행 대상이 아닙니다.

[통합 서버 설치·실행·테스트](ROUTER.md)를 참고하세요. 통합 품질 보고서는 <http://localhost:5190/reports/router/>입니다.

## 3D 파크

전체 지도에서 마우스로 드래그하면 별의 정중앙을 기준으로 회전합니다. 스크롤로 확대·축소해도 중심이 고정되며, 우클릭·수정키 드래그로 화면이 밀리지 않습니다. 가까이 보던 장면에서 전체 지도로 돌아오는 도중 드래그해도 중심 회전을 유지합니다.

작은 별의 성, 숲, 호수, 개울, 마을과 각 어트랙션은 직접 만든 Three.js 지오메트리입니다. 물리 기반 재질, 절차적 석재·잔디·지붕 텍스처, 환경 반사, 4096px 그림자, 화면 공간 음영, 블룸과 ACES 톤 매핑을 사용합니다. 정적 건물을 재질별로 배치 렌더링하고, 움직이는 캐릭터와 놀이기구는 별도 유지합니다.

지도는 [B612 참고 이미지의 첫 번째 그림](https://lampy4.blogspot.com/2017/06/b612.html)처럼 **숲·호수·개울·산책로가 이어지는 작은 별**입니다. 잔디와 물 텍스처는 코드로 생성하며, 실제 지구 지도나 참고 이미지 파일을 배경으로 사용하지 않습니다. 테마의 바닥과 주변 땅을 구면에 맞춰 휘게 하고 건물은 표면 바깥 방향으로 세웠습니다. 범퍼카 등 움직이는 오브젝트도 곡면의 높이를 따라갑니다. 별 뒤에 가려진 라벨은 숨깁니다. 어트랙션을 선택하면 해당 테마로 이동하고, 전체 지도 버튼으로 별 전체를 다시 볼 수 있습니다.

위쪽 언덕에는 디즈니 성이, 앞쪽 중앙 광장에는 **공식 GS 그룹 CI의 주황·초록·파랑 심벌과 파란 GS 워드마크**가 있습니다. 로고는 별을 내려다볼 때 읽을 수 있도록 광장 표면에 놓았습니다. HDR 자연광, 석재·지붕 요철, 숲 인스턴싱, 작은 마을과 풍차를 사용합니다. [에셋 출처](assets/ATTRIBUTION.md)를 함께 보관합니다.

성 위에서는 다섯 색상의 폭죽이 발사 → 개화 → 잔광 순서로 계속 반복됩니다. **성 불꽃놀이 보기**를 누르면 밤으로 전환하고 성을 가까이 보여줍니다. 소리는 자동 재생하지 않습니다. 운영체제 또는 관람 환경의 움직임 줄이기 설정에서는 캐릭터와 폭죽을 고정된 장면으로 보여줍니다. 폭죽 입자 버퍼는 재사용하며 시간이 지나도 입자 수가 늘어나지 않습니다.

캐릭터는 움직이는 팔과 몸체를 나누어 재질별로 묶고, 어트랙션 교체 시 이전 GPU 리소스를 해제합니다. 프로젝트 입장 검증 중에는 가려진 파크의 렌더링을 잠시 멈춰 실제 프로젝트와 GPU를 동시에 점유하지 않도록 합니다.

미키·미니·도널드·올라프에 **데이지·구피·플루토·곰돌이 푸·스티치·베이맥스**를 더해 총 10종의 직접 구성한 3D 팬 아트 캐릭터가 있습니다. **친구들 만나기**에서 이름을 선택하면 캐릭터 앞으로 카메라가 이동합니다. 손 흔들기, 운전, 춤, 플루토의 꼬리와 스티치의 귀 모션을 사용합니다. 공식 게임 모델이나 디즈니 제공 파일을 사용하지 않으며, 디즈니의 공식 서비스가 아닙니다.

- `dopamin`: 범퍼카 / 미키
- `movie`: 영화관 / 미니, 기존 30초 영상 상영
- `voice`: 음악·음성 스테이지 / 도널드
- `map`: 아틀라스 공사장 / 타워크레인과 연구소 골조
- `pinball`: 대형 핀볼 머신 / 올라프
- `webpage`: 어트랙션 탐색과 프로젝트 에셋 경로에서 제외
- 다른 프로젝트: README·package 설명으로 테마를 추론하거나 `attraction.json` 설정 사용

참고 구도: [사용자가 지정한 미니어처 성과 정원](https://kr.pinterest.com/pin/380413499779233376/). 참고 이미지를 홈페이지의 배경으로 붙이는 방식이 아니라, 실제 카메라 회전·확대가 가능한 모델로 구성합니다.

## 10분 간격 커밋 감시와 Git 훅

별도 터미널에서 다음을 실행합니다.

```sh
npm run park:hooks
npm run park:watch
```

`post-commit`, `post-merge`, `post-checkout`, `post-rewrite` 훅은 감시 프로세스에 즉시 새 확인을 요청합니다. 기존 훅이 있으면 원본을 보존하고 먼저 실행합니다. **훅은 시간 예약 기능이 아니므로**, 별도의 장기 실행 Node 프로세스가 정확히 600,000ms마다 원격 커밋을 확인합니다. 감시 프로세스를 종료하면 정기 확인도 종료됩니다. 운영실은 PID 생존 여부와 최근 heartbeat를 함께 확인해 감시 실행 상태를 표시합니다.

동기화는 `git fetch origin`으로 시작합니다. 원격이 앞서고 작업 폴더가 깨끗하며 로컬 전용 커밋이 없을 때만 `git merge --ff-only origin/main`을 실행합니다. 다른 에이전트의 수정 사항이나 분기된 이력이 있으면 병합을 보류하고 운영실에서 알려 줍니다. 자동 reset, stash, 강제 푸시는 수행하지 않습니다. 네트워크 실패 시 로컬 파크는 계속 운영합니다.

한 번만 확인: `npm run park:sync`. 운영실의 새로고침 버튼도 감시 프로세스에 즉시 확인을 요청합니다. `.park-runtime/`에는 로컬 상태·이벤트·PID·heartbeat만 저장되며 Git에서 제외합니다.

새 프로젝트와 테마 변경은 `/api/events`를 통해 브라우저에 전달되어 지도에 반영됩니다. 각 프로젝트의 [attraction.json 설정](ATTRACTIONS.md)을 참고하세요.

## 기본 검증

### 끝없이 반복하는 실제 입장 검증

```sh
npm run park:circuit
```

현재 발견된 모든 어트랙션에 순서대로 입장합니다. 마지막 어트랙션을 마치면 10초 뒤 첫 번째부터 다시 시작하며, 매 회차 목록을 새로 읽어 추가된 프로젝트도 포함합니다. `Ctrl+C`로 종료하기 전까지 반복합니다. 한 회차만 실행하려면 `npm run park:circuit -- --once`를 사용합니다.

[무한 순회 HTML 보고서](http://localhost:5190/reports/circuit/)에 현재 회차·어트랙션·실패 원인·최근 화면·heartbeat를 실시간으로 기록합니다. 영화관은 실제 영상 재생과 정지를, 핀볼은 게임 시작과 일시정지를, 일반 웹 프로젝트는 실제 프로젝트 입장·렌더링·브라우저 예외를 확인합니다. 음성 스테이지는 호출/실행 안내를 확인하며, 다른 에이전트가 사용 중인 네이티브 마이크 프로세스를 시작하거나 종료하지 않습니다.

실패한 어트랙션도 근거를 남긴 뒤 다음 어트랙션으로 진행합니다. 실패를 통과로 간주하지 않습니다. 진행 중인 다른 프로젝트의 수정 사항은 이 홈페이지 에이전트가 임의로 커밋하지 않습니다.

개발 서버 실행 후:

```sh
npm run park:test:coverage
npm run park:test:golden
npm run park:reports
```

골든 기준을 의도적으로 변경할 때만 `npm run park:test:golden:update`를 실행하고 생성된 PNG를 직접 검토합니다. 그 다음 **스냅샷 업데이트 옵션 없이** `npm run park:test:golden`을 실행해야 회귀 검증이 됩니다. Playwright는 설치된 Google Chrome을 사용합니다.

기본 골든은 협업 중 새 프로젝트가 추가되어도 비교할 수 있도록 `dopamin`, `movie`, `voice` 세 어트랙션으로 고정한 테스트 카탈로그를 사용합니다. 실제 운영 화면과 무한 순회는 모든 현재 프로젝트를 사용합니다. 새 테마의 모델 생성·교체는 별도 브라우저 검사로 확인합니다.

- 핵심 문장·분기 커버리지: `park/lib/`의 프로젝트 탐색·설정·동기화, 구면 배치와 폭죽 주기 로직, V8 기반 HTML 보고서.
- 브라우저 실행 커버리지: 골든·기능 시나리오가 실제 실행한 `park/src/`의 V8 범위. 변환된 JavaScript 길이 기준이며 원본 문장 커버리지와 구분합니다.
- 골든: 작은 별의 데스크톱 낮·밤, 범퍼카 근접, 극장 스크린, 모바일 전체·음성 스테이지, 성 불꽃놀이, 친구 목록과 새 캐릭터 6종의 근접 화면.
- 기능: 실제 WebGL 컨텍스트·지오메트리, 구면 위 테마 위치와 방향, 폭죽 반복·움직임 줄이기, 캐릭터 선택·모션, 영상 재생·정지·탐색, 메뉴·카메라·화질 설정, 새로운 테마 모델 교체, HTTP Range와 에셋 접근 경계.

모든 결과는 `park/reports/`에 저장하고 로컬 `/reports/`에서 제공합니다. 보고서에 검증 대상과 한계를 표시합니다. GPU·브라우저·OS 차이에 따른 화면 차이는 발생할 수 있으며, 소프트웨어 렌더러의 FPS는 실제 GPU 성능을 대표하지 않습니다.

## 구조

```text
park/src/             화면, 3D 세계, 건물, 캐릭터, 재질
park/lib/             프로젝트 탐색과 동기화
park/scripts/         커밋 감시, 훅 설치, HTML 보고서
park/tests/unit/      핵심 로직 검증
park/tests/e2e/       브라우저·골든 검증과 기준 PNG
park/server.mjs       로컬 API, 영상 전송, Vite, 프로젝트 실행
```
