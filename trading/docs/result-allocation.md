# 주문 결과 문자열 할당 감소

신규 명령의 결과와 중복 방지 사본을 만들 때마다 상태·코드·메시지의 고정 문자열을 복제하던 할당을 줄였다. `CommandResult`의 세 필드만 `String`에서 `Cow<'static, str>`로 바꾸고 신규 결과는 정적 문자열을 빌린다. 기존 JSON을 읽을 때는 소유 문자열로 복원하므로 알 수 없는 코드나 메시지도 보존한다. 주문의 `Order.status`, 거래 규칙, 요청 이력 보존, 저장소 형식과 ACK 순서는 그대로다.

Rust 라이브러리 필드 타입은 바뀐다. 외부 Rust 코드가 직접 결과를 만들면 문자열에 `.into()` 등이 필요하다. HTTP·WebSocket·저장 파일에서는 같은 JSON 문자열이며 스키마를 바꾸지 않는다.

## 동일 입력 할당 실험

[원본 실험](../evidence/20260921T134615285Z-cow-result-prototype-5d8dd1e4/README.md)은 원본·후보 라이브러리를 별도 디렉터리에서 release로 빌드하고 동일 입력을 실행했다. 각 변형마다6,000개 명령을 준비 운동으로 처리한 뒤6,000개 신규 명령을 계측했다. 계측 범위는 `Core::execute` 진입부터 결과 반환까지이며, 미리 만든 입력·반환 결과의 해제·JSON 출력은 제외한다. 실행 중인 시연과 함께 수행했으므로 조용한 처리량 시험이 아니다.

| 측정6,000개 신규 명령 | 기존 | 변경 |
| --- | ---: | ---: |
| alloc 호출 | 85,987 | 49,987 |
| realloc 호출 | 1 | 1 |
| 명령당 alloc+realloc | 14.331333 | 8.331333 |
| 요청한 할당 바이트 합 | 5,034,232 | 4,446,232 |
| 결과 타입 크기 | 184 B | 184 B |

모든 신규 정상 명령에서 정확히6회·98바이트가 줄었다. 신규 거절도6회, 메모리에 유지된 새 결과의 중복 요청·조회·충돌은3회 줄었다. JSON/스냅샷에서 읽어 소유 문자열이 된 기존 결과의 중복 요청·조회는 줄지 않았다. 저널 재생은 다시 실행하면서 정적 문자열을 만들 수 있으므로 복구된 캐시 전체를 같은 경우로 묶지 않는다.

전체6,784개 원시 계측 행에 대한 [독립 재계산](../evidence/2026-09-21T14-00-48-017Z-cow-allocation-independent-review-4b10109d/README.md)이 일치했다. 후보도 명령당4~23회 할당하여 **zero allocation 목표는 미달**이다. 바이트 합은 상주 메모리나 최대 사용량이 아니며, TPS·지연·서비스 CPU 개선은 이 실험에서 측정하지 않았다.

## 응답·저장 데이터 호환성

각 측정 결과의 JSON 바이트와 최종 전체 Core JSON이 원본과 같았다. 전체 Core6,684,357바이트의 SHA도 동일하다. 알려지지 않은 코드·메시지와 이스케이프 문자열을 포함한 역직렬화, 역사적13개 입력의 결과·전체 상태, 새 스냅샷·저널 프레임 바이트도 대조했다. 저장 형식은 CRC 헤더를 포함하는 v1 JSON 프레임이다.

첫 실험은 스냅샷4 이후9개를 처리하고 새 스냅샷을 만든 뒤 재시작했으므로 비어 있지 않은 저널 후속분의 재생 증거가 아니었다. [추가 양방향 복구](../evidence/20260921T134615285Z-cow-result-prototype-5d8dd1e4/suffix-replay-v2/README.md)는 스냅샷4를 그대로 두고 저널13까지 기록한 뒤 닫았다. 원본이 쓴 데이터를 후보가, 후보가 쓴 데이터를 원본이 각각 열어 **후속9개 레코드를 실제 재생**했다. 전체 Core·조회·재시도·충돌 결과가 일치했다.13입력 중2개는 중복·충돌이어서 최종 명령 순번과 고유 요청 수는11이다.

[저장소 독립 검토](../evidence/2026-09-21T13-56-14-842Z-cow-result-independent-review-542cdb2f/review.md)는 원본 해시·프레임 CRC·JSON·할당 산술60개 조건을 대조했다. 운영 회귀의 `core_status_compatibility.rs`도 스냅샷 이후9개 저널 재생과11개 저장된 요청 결과를 확인하도록 강화했다. 기존 String 모델에서 먼저2개 검사를 통과했다. 초기 테스트가 중복 응답의 `duplicate=true`를 저장된 최초 결과와 비교한 실패는 보존하고, 계정·요청 ID별 최초 결과를 비교하도록 수정했다.

## 적용 검증과 남은 측정

운영 적용 후 [전체 Rust 타깃48개 테스트·Clippy·fmt·release 및 복구 도구 빌드](../evidence/20260921T140412010Z-cow-production-validation-c19b5acd/)를 통과했다.48개에는 같은 WS 인코더 검사3개가 main과 예제에 각각 포함된다. [API10개 회귀](../evidence/20260921T140736706Z-cow-api-regression-0e07f8da/run.json)는12동시 클라이언트·응답 유실·강제 종료·재시도·WS재연결·checkpoint실패를 포함한다. [새 복구 도구 자체 검사](../evidence/20260921T140736677Z-cow-aged-validator-selftest-76a29842/run.json)도 통과했다. 최초 포맷 검사는 함수 서명의 줄바꿈으로 실패했고 원본을 보존한 뒤 rustfmt로 정리했다.

[후속 독립 검토](../evidence/2026-09-21T14-05-25-414Z-cow-suffix-independent-review-27672a0b/review.md)는 양방향 저널 재생의 원본67개 조건을 재계산하고, 적용된 소스가 후보에서 import 순서와 함수 줄바꿈만 바뀌었음을 정확한 치환으로 확인했다.

| 검증한 실행 파일 | SHA-256 |
| --- | --- |
| 새 release 엔진 | `65348c203d3ddf0a29cb3fa19eca650347e4cd77308f2352f434212063896512` |
| 새 release 코어 벤치마크 | `7cfd820a78d0f2ce1cac442f5da941e817e23e880e8cf0653a76c7c037df1a86` |
| 새 debug 전체 복구 도구 | `d2c8dd9ed9315d6859be5350f5b2e8c909594735d6000a4c7a0c30966ad14d43` |

6시간 관찰 중인 엔진은 이전 바이너리를 계속 사용한다. 실제 종료 뒤 누적 데이터의 전체 복구를 검증하고 새 바이너리로 시연을 재개한다. 최신 바이너리의 조용한 A/B/C 측정은 별도로 시행해야 하며, 이번 격리 할당 수치를 그 결과로 대신하지 않는다.

## 남은 할당과 다음 변경의 범위

[기존 원자료 6,784행의 단계별 분석](../evidence/20260921T145034129Z-post-cow-allocation-map-62b869b0/review.md)에서 신규 정상 명령 6,000개의 합계는 위 결과와 일치했다. 취소는 평균4.14–4.188회, 미체결 주문은7.118–7.156회, 두 건 체결 주문은20.245회였다. 각 단계는1,000건이며 입력 분포가 다른 전체 서비스의 평균으로 일반화하지 않는다.

소스에는 요청 ID와 계정 ID의 결과·중복 방지 사본, 주문 문자열, 체결 이력과 반환 결과의 깊은 복사, 요청 트리·가격 큐·이력 증가 경로가 남아 있다. 이 목록은 소스 분석이며 개별 경로의 할당 기여량을 실측한 것은 아니다. 기존 중복·조회 표본은 체결 목록이 빈 결과이므로 그2회 또는5회 수치를 다중 체결 결과 조회에 적용하지 않는다.

예정된 A/B/C 비교와 누적 복구를 먼저 마친 뒤, 다음 후보는 주문 상태의 정적 표현 또는 별도 가격 큐 버퍼 재사용 중 하나를 격리하여 검토한다. 요청·체결 결과 공유는 저장 형식, 스레드 전달, 보장 기간 동안의 중복 결과 보존까지 함께 설계해야 한다. 입력 변환을 측정 구간 밖으로 옮기거나 이력을 삭제하여 무할당으로 표시하지 않는다. 이번 분석에서는 운영 코드·바이너리·서비스를 변경하지 않았다.

00:48의 [Order.status Cow 적용 전 패치](../evidence/20260921T154523346Z-order-status-cow-proposal-6dbe824f/review.md)는 이 다음 후보를3파일·5개 변경 구간으로 구체화했다. 기존 JSON에서 읽은 status는 Owned를 유지하고 성공한 상태 전환만 정적 문자열로 바꾼다. 단순 enum이 알 수 없는 과거 문자열의 거절 시점을 바꾸는 점을 피하는 안이다. 현재 운영 소스·바이너리에 적용하거나 빌드하지 않았다. 정상6단계 중 신규 place4단계의 기존 status 할당이 영향 대상이라는 소스 가설이며 실제 절감량·속도·메모리 개선 증거는 아직 없다. 현재653/7cfd/d2c8의 quiet 비교를 먼저 완료한다.
