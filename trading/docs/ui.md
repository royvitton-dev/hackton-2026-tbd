# 독립 휴가 거래소 UI

`trading/frontend`는 통합 놀이동산 앱·로그인·다른 어트랙션 없이 직접 실행하는 휴가 거래소다. 사용자 추가 지시인 “이거만 확인할 수 있는 UI”의 기본 제공 형태다. 주소는 `http://127.0.0.1:5175`이며 화면 제목은 **LEAVE PARK — 휴가 거래소**다.

## 실행

전체 시연 시작은 `trading/README.md`의 통합 실행 절차를 따른다. UI만 따로 실행하려면:

```powershell
Set-Location C:\project\hackton-2026-tbd\trading\frontend
pnpm install --store-dir ../.tools/pnpm-store
pnpm dev
```

Rust 엔진 기본 주소는 `http://127.0.0.1:8787`, 스트림은 `ws://127.0.0.1:8787/ws`다. `.env.example`을 참고해 `VITE_API_URL`과 `VITE_WS_URL`을 설정할 수 있다. 엔진 없이 열면 연결 대기·빈 시장·비활성 주문 버튼을 표시한다. 프런트엔드가 가격이나 체결 데이터를 만들어 채우지 않는다.

| 파크 크루 | API가 반환한 실제 봇 ID·전략·seed·heartbeat·누적 주문·체결. 연결 신호가 있어도 heartbeat 15초 초과면 연결 대기 표시 |
| 하단 상태 | 엔진 상태, 마지막 이벤트 순번, 누락 감지 후 재동기화 횟수, 마지막 수신 시각 |

주문·체결 수는 계정의 엔진 누적 `orders_count` / `trades_count`를 우선 사용한다. 전략 펼침에는 봇 heartbeat가 보고한 API 시도 수를 따로 표시한다. 봇 메타데이터와 모의 세션은 3초마다 조회한다. 1초 화면 시계는 heartbeat 경과 시간만 갱신하며 거래 가격·체결·잔고는 조작하지 않는다.

회사 표시는 사용자 요청에 따라 GS리테이·GS칼테스·GS건썰이다. 세 계정은 `/api/sessions`가 제공하는 명시적인 로컬 모의 세션 토큰으로 구분한다. 브라우저에 보이는 데모 토큰은 인증 비밀값이 아니며 실제 인사·금융 인증을 의미하지 않는다.

## 주문 결과와 재연결

1. 주문마다 `crypto.randomUUID()` 요청 ID를 한 번 발급한다. 요청 본문·모의 계정·토큰과 처리 상태를 브라우저에 보존한다.
2. 제출 중, `durable:true` 확정 성공, 확정 거절, 결과 미확인을 구분한다. 정상 HTTP 응답이며 계정·요청 ID가 일치하는 정식 결과만 확정 처리한다. 큐 접수 또는 `durable:false`를 확정 성공으로 표시하지 않는다. 5xx·저장소 실패는 명령이 디스크에 기록됐을 가능성이 있어 결과 미확인을 유지한다.
3. 네트워크 오류·8초 타임아웃·확정 응답이 아닌 HTTP 결과는 미확인으로 표시한다. 미확인은 `/api/requests/:request_id` 조회 또는 **같은 ID와 동일한 내용** 재전송으로 해소한다.
4. 새로고침 중이던 요청은 미확인으로 복원한다. 완료 결과는 최근 20개를 보존하되 미확인·제출 중 요청은 이 표시 제한으로 제거하지 않는다. 브라우저 저장소가 차단되면 현재 탭 메모리만 유지되므로 새로고침 복원은 보장되지 않는다.
5. 초기 HTTP 상태 조회와 WebSocket 구독은 병행한다. 각 스트림 메시지는 전체 스냅샷이다. 이전 또는 동일 이벤트 순번의 거래 상태는 중복으로 무시한다. 저장소 실패는 거래 순번을 늘리지 않을 수 있으므로 동일 순번의 `engine_status` 변경만 별도로 반영한다. 과거 HTTP 응답이나 이미 대기 중인 WS 응답이 실패 상태를 정상으로 되돌릴 수 없다. 실패를 인지한 뒤 새로 연결한 구독의 첫 스냅샷만 같은 순번의 복구를 확인할 수 있다. 순번 누락을 감지하면 받은 전체 상태를 적용하고 HTTP 전체 상태도 다시 조회한다.
6. WebSocket 단절 시 마지막 확정 상태와 재연결 안내를 유지하고 새 주문을 비활성화한다. 0.5초부터 최대 8초까지 지수 간격으로 재접속한다. 재접속 최초 전체 스냅샷으로 시장 상태를 복원한다. 엔진 상태가 `ready`일 때만 주문할 수 있으며 `failed_closed` 상태는 저장소 오류·거래 중단으로 표시한다.
7. 이벤트 순번이 역행하면 데이터셋 변경 가능성을 알리고 새로고침을 안내한다. 더 오래된 상태로 잔고를 되돌리지 않는다.
8. 계정별로 요청 조회·재시도·신규 주문·취소 중 한 작업만 진행한다. React 화면 갱신 전의 빠른 연속 클릭도 동기 잠금으로 막는다. 조회와 재시도가 동시에 실행되어 과거 조회 결과가 확정 결과를 덮어쓰는 일을 방지한다. 다른 모의 계정은 독립적으로 작업할 수 있다.

## 디자인과 접근성

기존 `dopamin`의 React 19 / TypeScript 5.9 / Vite 7 구성, DM Sans·Noto Sans KR, 크림 `#f7f7f2`·먹색 `#30382e`·오렌지 `#fa623c`를 재사용했다. 새 로고·작은 놀이공원 도안은 코드 기반 SVG이고 주문 패널은 절취 티켓 형태다. 외부 이미지·실제 회사 로고·새 온라인 자산 서비스에 의존하지 않는다.

데스크톱은 차트·호가·주문 입력을 병렬 배치하고 좁은 화면에서는 모두 세로로 접근할 수 있다. 작은 화면에는 주문 입력과 보관함을 먼저 배치한다. 폼 label, 키보드 focus, 상태 안내 `aria-live`, 차트 설명, 버튼 접근성 이름, reduced-motion 설정을 제공한다. 실제 UI 브라우저 검증 결과는 `trading/evidence`의 해당 run ID를 확인한다.

매수·매도, 수량 선택, 차트 표시 범위, 주문 목록 선택은 `aria-pressed`로 현재 선택을 알린다. 입력 범위를 벗어나면 폼에 구체적인 정수·범위 안내를 표시하고 `aria-invalid` 및 설명 연결을 제공한다. 주문 버튼이 비활성화될 때 입력 오류·엔진 단절·거래 중단·작업 진행 상태를 구분해 설명한다. 클릭과 키보드 Enter는 동일한 폼 제출 경로를 사용한다.

## 선택적인 루트 통합

**실제 적용 상태: 미적용.** 루트 파일은 읽기만 했으며 독립 실행에 필요하지 않다. 차후 승인을 받고 통합할 경우 기존 루트 메뉴에 `http://127.0.0.1:5175` 링크를 추가하거나 HTTPS 독립 거래소 주소를 링크할 수 있다. 프런트엔드 내부에는 `/`, `#market`, `#my-orders`, `#bots` 진입점이 있다. 배포 주소를 루트에서 주입하는 별도 링크 컴포넌트만으로 연동 가능하다.

타입 검사를 포함한 최소 컴포넌트는 `frontend/src/integration/ExchangeLink.tsx`, 호스트 설정·삽입 예시는 [연동 어댑터 절차](integration-adapter.md)에 있다. 이 컴포넌트도 루트에 적용하지 않았다.

적용 예시(승인 전 루트 수정 금지):

```tsx
<a href={exchangeUrl} target="_blank" rel="noopener noreferrer">휴가 거래소 열기</a>
```

루트 전체의 CSS나 상태를 가져오지 않아 거래소의 실행·배포·복구가 기존 놀이동산 앱과 독립적이다.

## 검증 명령

```powershell
pnpm build
pnpm test
pnpm format:check
```

프로토콜 테스트 7개는 중복·역행·누락 순번 처리, 내구성 없는 ACK의 미확인 처리, 계정·요청 ID 일치, 새로고침 요청 복원, 미확인 요청 보존, 같은 순번의 실패 상태 보호, 계정별 조회·재시도 및 연속 제출의 배타 실행을 검증한다. 빌드 검증은 TypeScript strict 검사와 실제 Vite production bundle을 포함한다. `scripts/verify.ps1`은 형식 검사·프로토콜 테스트·빌드의 원본 로그를 새 evidence run 디렉터리에 보존한다. 이 테스트만으로 실제 브라우저 주문·취소·재연결이 검증됐다고 주장하지 않는다.

2026-09-21 17:37~17:38 KST에 실제 엔진·12개 봇이 실행 중인 통합 화면을 브라우저로 확인했다. `evidence/frontend-20260921T083739Z-visual`에 1440px 데스크톱, 봇 활동, 390px 모바일 주문·차트, 1024px 태블릿 화면을 저장했다. 세 너비 모두 문서 가로 넘침이 없었고 신규 탭의 console error/warn은 없었다. 실제 체결 80건/240건 전환, 세 회사 모의 세션, 엔진 누적 주문·체결 수와 12개 봇 heartbeat가 표시됐다. 이 시각 검증에서는 주문·취소를 제출하지 않았으며 거래 행위의 검증은 별도 통합 시나리오 기록을 따른다.

별도 API·WebSocket 관찰 `evidence/2026-09-21T08-35-49-326Z-observe-828e38ca/summary.json`은 309.945초 동안 62회 샘플, 거래량 1,353시간 증가, 체결 가격 32종, 12개 봇 주문 참여 및 체결, 연결 봇 최소 12개, WS 이벤트 1,848개와 gap·단절 0을 기록했다. 이 결과는 5분 이상의 **서버/API·스트림 관찰**이다. 브라우저를 연속 5분 녹화하거나 각 프레임 렌더링을 검증했다는 의미는 아니다.

실제 브라우저 주문·취소 기록은 `evidence/browser-manual-20260921T083933Z/README.md`에 별도로 있다. 이 기록은 부분 체결 후 취소, 예약 해제, 키보드 제출의 체결 및 잔고 변화를 확인했다. 한 번의 입력 후 클릭은 변화가 없었고 당시 기록은 체결 증거로 쓰지 않는다. 클릭 문제의 원인은 확인되지 않았으므로 재현 결과와 구분한다.

별도 [브라우저 장애 재현 증거](../evidence/2026-09-21T09-04-20-029Z-browser-fault-ade34c84/)에서는 실제 내구성 기록 후 ACK를 가로막아 504를 반환한 경우를 검증했다. 조용한 시장에서 UI가 재연결 표시로 머무르던 결함을 고쳐 5xx 후 실제 WS 재구독을 시작한다. 수정 후 새 체결 없이 다시 연결됐고, 새로고침으로 미확인 요청을 복원한 다음 같은 ID를 재전송하여 기존 주문 #3 결과를 조회했다. 엔진의 명령 순번 3·주문 수 3·예약 2,575 P가 그대로 유지돼 중복 주문이 생기지 않았다. 원래 실패 화면과 수정 후 화면을 모두 보존했다.
