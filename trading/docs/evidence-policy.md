# 증거 보존·Git 포함 범위

매 실행은 고유 run ID 디렉터리를 만든다. 통과·실패·미완료 로그를 모두 보존하고, 수정 뒤의 재검증은 새 디렉터리에 저장한다. 체크포인트·문서·동일 실행의 `latest-state.json`처럼 명시적으로 최신 상태를 나타내는 파일은 갱신하며, 원본 표본은 append-only JSONL로 남긴다.

`trading/.gitattributes`는 이 경계 안의 Git 줄바꿈 자동 변환을 끈다. 캡처한 소스·원본 출력·fixture의 바이트와 SHA-256을 checkout 플랫폼에 따라 바꾸지 않기 위함이며, 소스 포맷은 각 formatter가 관리한다.

Git에는 코드·테스트·설정·문서, 검증 명령/종료코드/환경, 성능 원본 JSON/로그, 실제 브라우저 화면과 요약을 포함한다. 사용자 추가 지시로 완성 변경의 기존 Git remote push가 승인됐다. 도구 다운로드·의존성·캐시·빌드 디렉터리·복사 실행 바이너리·런타임 `data` 디렉터리는 `.gitignore`로 제외한다. 제외는 삭제가 아니며 원본 데이터와 바이너리는 로컬 `trading`에 보존한다. 다른 사람이 재현할 때 README와 lockfile로 빌드하고 새 합성 데이터를 사용한다.

누적 데이터 복구 도구의 전체 runtime Core JSON 사본(`snapshot-recovered-full-core.json`, `journal-replayed-full-core.json`)도 동일하게 로컬에 보존하고 Git에서 제외한다. 장시간 실행에서 같은 전체 상태의 중복 사본이 매우 커질 수 있기 때문이다. 비교 결과·해시·원본 파일 목록·명령은 Git에 포함한다. 작고 고정된 호환성 입력인 `engine/tests/fixtures/*.json`은 추적하여 테스트가 로컬 제외 파일에 의존하지 않게 한다.

새 봇 로그의 `round_trip_ms`는 실제 HTTP 명령 제출부터 응답 JSON 처리까지의 클라이언트 관찰 시간이다. `scripts/summarize-bot-latency.mjs <demo-run-id>`는 durable 응답과 불명확 응답/조회 결과를 구분하고 15분 구간별 분포를 새 evidence에 저장한다. 기존 기록에 없는 시간은 추정하지 않는다. observer의 상태 조회 응답 시간도 별도로 보존하며, 이 수치를 순수 코어 지연이나 조용한 성능 벤치마크로 표시하지 않는다.

봇별 JSONL 로그는 5 MiB마다 새 파일을 열며 자동 삭제하지 않는다. 장시간 관찰은 5초 시장 표본, 30초 프로세스 메모리·디스크 여유·실제 로그 용량·영속 데이터 용량을 기록한다. 명령/주문/체결/중복 요청 이력은 데이터셋 수명 동안 보존하므로 메모리와 디스크가 증가한다. 주기적 스냅샷은 30분마다, 추가로 명시적 checkpoint/종료 때 생성한다. 자동 compaction이나 이전 증거 삭제는 없다. 여유 공간과 용량 도달 거절을 관찰하여 운영자가 새 시연 데이터셋을 별도로 선택할 수 있다.

`docs/agents.jsonl`은 실제 collaboration 도구에서 확인한 에이전트 ID와 담당 업무, 관찰한 시각을 기록한 **작업 요약**이다. 원본 Codex 세션 export는 수행하지 않았으며 원본 전체 세션 로그라고 표시하지 않는다. 원본 실행 명령·stdout/stderr·종료코드·테스트 결과·화면 증거는 가능한 범위에서 `evidence`에 수집했다. 정확히 확인하지 못한 에이전트 시작/종료 시각은 null 또는 관찰 시각으로 표시한다. 숨겨진 내부 추론은 기록하지 않는다.

프로세스 목록/경로는 측정 환경 증거다. 모든 계정·토큰·자산은 공개된 합성 시연 식별자이며 실제 개인정보나 서버 비밀정보를 기록하지 않는다. 외부 배포 및 실제 시스템 연결은 하지 않았다.

## 관찰 공백과 유휴 절전

2026-09-21 18:29:58.874–18:35:54.475 KST의 Windows Modern Standby355.600초를 시스템 이벤트506/507과 실제356.739초 표본 공백으로 확인했다. 이 구간을 실제 작업 시간이나 연속 시연 시간에 포함하지 않는다. [시스템 원본/요약](../evidence/20260921T093839163Z-host-standby/summary.json)을 보존했다. 진행 중이던 1시간 관찰의 기존 코드에는 이 조건이 없으므로 그 실행이 기존 `passed:true`를 기록하더라도 **연속1시간 검증으로 인정하지 않는다**. 새 분석의 `sampling_continuity`와 이 해석을 함께 사용한다.

보완한 관찰기는 5초 간격 표본 사이15초 초과 공백을 별도로 실패 처리한다. WebSocket sequence 누락이 없더라도 전체 호스트가 멈춘 시간을 검출하기 위함이다. 기존 연속5분 원본은 통과, 절전이 포함된 원본은 공백1개 검출을 [실제 표본 회귀 확인](../evidence/2026-09-21T09-39-51-834Z-continuity-regression/result.json)으로 검증했다.

Windows 관찰 실행 중에는 `keep-awake.ps1`이 해당 관찰 프로세스 수명 동안 `SetThreadExecutionState`의 SYSTEM_REQUIRED 요청을 유지하고 종료 시 해제한다. 화면 켜짐 요청이나 영구 전원 설정 변경은 없다. 사용자에 의한 명시적 절전·종료를 막는 보장이 아니며 `OBSERVE_ALLOW_IDLE_SLEEP=1`이면 요청하지 않는다. [10초 도구 기능 확인](../evidence/2026-09-21T09-39-51-901Z-observe-b75b75a0/keep-awake.json)에서 시작과 정상 해제를 확인했으며 이는 장시간 시연 통과 근거가 아니다. `powercfg /requests` 목록은 관리자 권한 부재로 조회하지 못했고, API 성공·보조 프로세스 기록 및 이후 표본 연속성만 확인한다.
