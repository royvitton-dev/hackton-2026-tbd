# DROP LAND · 행운이 굴러오는 3D 놀이공원

친구들의 이름·번호·선택지가 붙은 공으로 당첨자와 순서를 정하는 무료 웹 게임입니다. **독자적인 긴 코스 4종, 네온 놀이기구가 있는 실제 3D 화면, 별빛 축제의 중앙 구멍 1개와 다른 맵의 구멍 4개로 구성한 결승부**를 제공합니다. 공의 충돌, 실제 도착 순서와 마지막 남은 공이 결과를 결정하며, 당첨자를 먼저 뽑고 경기를 꾸미는 코드가 없습니다. 결제·코인·환전·계정·실물 보상·광고·외부 API는 없습니다.

## 실행

Node.js 20 이상이면 패키지 설치 없이 실행됩니다. Three.js 0.183.0은 MIT 라이선스와 함께 `vendor/`에 포함되어 있어 런타임 CDN 연결이 없습니다.

```sh
cd /path/to/pinball
node scripts/serve.mjs
# 브라우저: http://127.0.0.1:4188
```

현재 작업 결과물에서 바로 실행하려면:

```sh
cd /Users/gschargev/Documents/Codex/2026-09-21/new-chat-4/outputs/pinball-rush
node scripts/serve.mjs
```

- 서버는 `127.0.0.1`에만 바인딩합니다. 종료는 `Ctrl+C`입니다.
- 포트가 사용 중이면 `PORT=4189 node scripts/serve.mjs`로 변경합니다.
- ES modules와 WebGL을 사용하므로 HTML 파일을 `file://`로 직접 열지 마세요.
- `npm start`, `npm test`, `npm run build`도 사용할 수 있습니다. `npm install`은 필요하지 않습니다.

```sh
node --test tests/physics.test.mjs tests/motion.test.mjs tests/finish-rules.test.mjs tests/devices.test.mjs tests/course-devices.test.mjs
node scripts/build.mjs
node scripts/serve.mjs --dist
```

## 조작과 참가자

1. 한 줄에 한 명씩 이름·번호·미션을 입력합니다. 빈 줄과 앞뒤 공백은 무시합니다.
2. 기본 공 수는 1개입니다. `하늘 | 3`처럼 줄마다 지정하거나, **참가자별 공 개수**를 펼쳐 수정합니다.
3. 첫 번째 도착·마지막으로 남기·지정 순위 도착 중 규칙을 선택합니다. 맵 4종 중 하나를 고릅니다.
4. **공 섞고 시작하기**를 누르면 1.8초 섞기 → 3초 카운트다운 → 출발 게이트 개방 순으로 진행됩니다.
5. 첫 번째·지정 순위는 그 순위의 공이 결승 구멍에 들어간 순간 바로 멈추고 당첨자를 크게 표시합니다. 마지막 규칙은 공이 하나만 남는 순간 바로 멈추며, 그 공이 당첨됩니다. 마지막 공을 허위 도착으로 기록하지 않습니다.
6. **다시 플레이**는 같은 설정에 새 난수를 사용합니다. 설정 변경 버튼으로 대기 상태로 돌아가 참가자·규칙·맵을 변경합니다.

| 항목 | 지원 범위 |
| --- | --- |
| 참가자 | 1~60명 |
| 참가자별 공 | 1~10개 |
| 전체 공 | **1~60개** |
| 이름 길이 | 유니코드 코드 포인트 1~40자 |
| 전체 입력 | 6,000 UTF-16 코드 유닛 이하 |
| 지정 순위 | 1~전체 공 수의 정수 |

동일한 이름은 별도 참가자로 유지합니다. 두 번째부터 `(2)`, `(3)`을 붙입니다. 이름을 자동 합치거나 공 수를 조용히 잘라내지 않습니다. `|`는 공 개수 구분자이므로 이름 자체에 사용할 수 없습니다. 여러 공을 가진 참가자는 도착 목록에 여러 번 등장할 수 있습니다. 긴 이름은 공 위에서만 축약하며, 참가자 목록과 결과에는 전체 이름이 표시됩니다.

- **일시정지·재개:** 공 위치, 순위, 장애물 위치와 경기 시간을 그대로 보존합니다. 섞기·카운트다운 중에도 동작합니다.
- **처음부터:** 현재 경기를 폐기하고 같은 설정의 대기 상태로 돌아갑니다. 이전 당첨·순위는 지워집니다.
- **크게 보기:** 경기장을 화면 중심으로 확대하고 출발·정지·배속 버튼을 가까이 둡니다. 원래 화면 버튼 또는 Escape로 돌아갑니다. 배치·시점 변경은 경기 상태에 영향을 주지 않습니다.
- **전체 맵 / 따라가기:** 긴 경기장의 전체 구조를 보거나 자동 카메라로 현재 진행 구간을 봅니다. 카메라는 판정에 관여하지 않습니다.
- **상단 / 입체 / 측면 시점:** 기본은 위에서 보는 고정 각도로 진행 구간을 따라갑니다. 경기장 우측 상단에서 3D 카메라 각도를 바꿉니다. 원근 카메라와 실제 입체 메시를 사용하며, 두꺼운 보드 측면·받침·그림자를 볼 수 있습니다. 정지 중 시점을 바꿔도 공과 순위는 움직이지 않습니다.
- **이름 간결하게 / 이름 모두 보기:** 기본은 겹치는 이름표를 줄여 공의 경로를 잘 보이게 합니다. 필요하면 모든 이름을 표시할 수 있습니다. 전체 이름과 도착 순위는 결과 목록에서 확인합니다.
- **1× / 1.5× / 2× / 3×:** 기본은 **1.5×**입니다. 대기 중·경기 중·일시정지 중 바꿀 수 있습니다. 더 많은 고정 물리 스텝을 실행해 재생만 가속하며, 순위·구멍 판정·경기 시간은 같은 물리 기준을 사용합니다.
- **살랑살랑 보드:** 시작 전에 켜거나 끕니다. 경기 시작부터 3~5초 사이의 시드 기반 무작위 간격으로 1.8초 동안 좌우로 약하게 기울며, 모든 공에 같은 방향과 세기의 실제 가속도를 줍니다. 경기 도중 설정은 잠깁니다. 시드와 시간만 사용하며 이름·순위·당첨 규칙은 참조하지 않습니다.
- **자석과 대포:** 모든 맵에 자석·대포가 하나씩 있습니다. 자석은 가까운 공을 당겨 실제 접촉 위치에서 0.5~1초 붙잡고 놓습니다. 대포는 V자 깔때기 안에 들어온 공을 같은 시간 동안 붙잡고 무작위 방향으로 회전한 뒤 초당 740 단위로 발사합니다. 대기 시간은 120Hz 시뮬레이션 기준이며 재생 속도에 따라 화면상의 시간도 빨라집니다. 한 장치당 공 1개만 포획하고, 방출한 공은 2초 동안 재포획하지 않습니다. 포획한 공은 다른 공과 계속 충돌하며, 공의 위치를 순간 이동시키지 않습니다. 이름·규칙·순위를 참조하지 않으며 시드가 같으면 대기 시간과 발사 방향도 재현됩니다.
- **네온 구간:** 각 코스의 세 구간에 네온 레일·별 조명·바닥 광륜이 있습니다. 빛은 천천히 변하고 연출 줄이기를 켜면 일정하게 유지됩니다. 판정에는 관여하지 않습니다.
- **큰 당첨자 안내:** 규칙을 달성하는 즉시 경기장 중앙에 이름과 당첨 이유를 크게 표시합니다. 첫 번째·지정 순위는 실제 도착 순위를, 마지막 규칙은 마지막 남은 공임을 표시합니다. 한 번 더 타기·전체 순위 보기 버튼을 제공합니다.
- **소리:** 기본 음소거. 충돌음·출발음·도착음·당첨음을 Web Audio로 합성합니다.
- **연출 줄이기:** OS 설정을 처음 반영합니다. 축하 조각·슬로모션·잔상·충돌 파동·보드의 시각적 기울임을 끄며 카메라 보간을 줄입니다. 경기 물리는 동일합니다.
- 브라우저 탭을 떠나면 자동 일시정지합니다. 돌아온 후 재개를 누르세요. WebGL context가 끊겨도 경기를 일시정지합니다. 그리기 오류가 발생하면 경기를 멈추고 오류 안내를 표시합니다. 화면 복구 버튼으로 같은 위치와 순위를 유지한 채 보드를 다시 만든 뒤 재개할 수 있습니다.
- 모바일에서는 설정 → 경기장 → 결과 순으로 배치되며, 시작할 때 경기장으로 이동합니다. 버튼은 터치와 키보드로 조작할 수 있습니다. 결과 안내는 라이브 영역으로 제공합니다.

## 물리와 판정

- 질량·반지름·반발 계수는 모든 공에 동일합니다. 반지름은 10 물리 단위입니다.
- 물리는 1/120초 고정 간격의 평면 시뮬레이션입니다. 중력, 공끼리의 충돌, 원형 핀·범퍼, 선분 레일·회전문·이동 장애물을 계산합니다. 일반 속도는 초당 560 단위, 대포 발사 직후 0.55초는 최대 780 단위로 제한하고 각 스텝에서 4회 충돌 보정을 수행합니다.
- 실제 3D 화면은 Three.js WebGL의 PerspectiveCamera와 입체 메시로 그립니다. 두께 0.8의 보드·뚫린 구멍·금속 핀·받침·조명·그림자·공의 반사광을 제공합니다. 공의 이동·충돌 계산은 보드 평면에서 이루어지며 자유 낙하하는 3축 강체 물리는 아닙니다. WebGL 초기화가 불가능한 기기에만 Canvas 2.5D 호환 화면을 제공합니다.
- 회전 막대는 맵 안에서 서로 다른 속도와 방향으로 움직입니다. 네 날개 풍차는 수직으로 교차하는 두 개의 실제 충돌 막대를 사용하고, 바이킹은 정현파 각도와 그 미분인 실제 각속도로 왕복합니다. 회전목마·우주선·범퍼카는 둥근 바닥 테두리가 실제 원형 충돌 범위입니다. 회전목마 범퍼의 반발 계수는 1.12로 작은 에너지를 더하며 공의 속도 제한은 유지합니다. 충돌 효과는 실제 접촉 이벤트에서만 발생합니다.
- 출발 위치와 순서는 `crypto.getRandomValues`에서 받은 시드와 Fisher–Yates 섞기로 결정합니다. 경기 중 무작위는 동일한 탈출 보조 규칙에만 사용합니다.
- 별빛 축제 결승 구멍 중심 x는 310, 폭은 80입니다. 다른 맵은 x=100·240·380·520, 폭은 64입니다. 각 구멍의 입구와 사이 경사 레일은 실제 충돌 대상입니다.
- 공 중심이 y=2,150 판정선을 **구멍 안쪽으로** 넘어가야 도착합니다. 같은 물리 스텝 안에서도 선형 보간한 통과 시각으로 순서를 매깁니다. 구멍 사이로 선을 넘는 비정상 경로는 집계하지 않고 되튕깁니다.
- 완전히 동일한 통과 시각은 시작 때 정한 무작위 우선값, 그 값까지 같으면 고유 공 ID로 판정합니다. 특정 이름이나 입력 순서에 유리한 당첨자 선정 기능은 없습니다.
- 각 공은 고유 ID와 `finished` 상태를 가지며 한 번만 집계됩니다. 첫 번째/N번째의 당첨자는 선택한 순위의 실제 도착 기록입니다. 마지막 규칙은 실제 도착이 N-1개가 된 시점의 미도착 공 하나를 당첨자로 선택하며 도착 목록에 추가하지 않습니다. 당첨 규칙은 종료 시점만 바꾸고 그 이전의 물리 경로·도착 기록을 바꾸지 않습니다.
- 종료 시점은 도착 판정에 사용한 세부 통과 시각으로 맞춥니다. 완전히 같은 시각에 통과한 공들도 시드 우선값으로 순서를 정하며 목표가 달성된 이후의 순위는 추가 집계하지 않습니다. 공 한 개로 마지막 규칙을 선택하면 출발 게이트가 열린 순간 그 공의 당첨을 확정합니다.
- `exportRound()`의 마지막 규칙 당첨자는 `criterion: last-remaining`, `crossedFinish: false`, `exitId: null`입니다. `rank`는 마지막 순서에 해당하는 전체 공 수를 나타내고 실제 도착 목록에는 포함되지 않습니다. 제품은 `finishMode: winner`로 실행하며, 물리 QA용 전체 코스 모드(`all`)는 마지막 공까지 추적해 지형의 정체·완주를 검사합니다.
- 슬로모션은 물리 스텝을 처리하는 화면 시간만 늦춥니다. 스텝 크기·난수·순위 판정은 바뀌지 않습니다. 같은 Chrome에서 연출·일시정지 없이 재실행한 결과가 화면 경기와 일치하는지 검증합니다.

## 정체·실패·무작위성의 한계

- 공이 기준 위치에서 20단위 이내에 4.5초 이상 머물거나, 8.5초 동안 아래로 24단위 이상 진행하지 못하면 좌우 무작위 방향의 동일한 크기 탈출 충격을 줍니다. 순간이동하거나 임의 순위를 부여하지 않습니다. 화면에 보조 횟수를 표시합니다.
- 당첨 조건을 달성하기 전에 경기 물리 시간 90초가 되거나 좌표에 비정상 값이 생기면 **무효 경기**입니다. 임의의 공을 당첨시키지 않으며 다시 플레이할 수 있습니다.
- 균등한 출발 섞기와 동일한 공 사양은 **당첨 확률이 완전히 같다는 증명은 아닙니다.** 지형·충돌 순서·수치 오차·공 개수·탈출 보조가 결과에 영향을 줍니다. 확률 검정이나 인증은 수행하지 않았습니다.
- 시드가 같아도 **다른 JS 런타임/브라우저/버전의 결과는 같다고 보장하지 않습니다.** Node와 Chrome 간 약 7.1e-15의 초기 수치 차이가 충돌 과정에서 커져 순서가 갈라지는 사례를 실제 확인했습니다. 제공한 시드는 같은 환경에서의 재현·디버깅용입니다.
- 연속 충돌 탐색이나 강체 전문 엔진을 사용하는 것은 아닙니다. 작은 스텝, 속도 제한, 반복 충돌 보정으로 검증 범위에서 관통·이탈을 방지합니다. 무한한 모든 입력·기기·실행 시간을 검증한 것은 아닙니다.
- 카메라 밖 공은 오른쪽 진행 막대로 표시됩니다. 많은 공이 겹친 구간에서는 이름표도 겹칠 수 있습니다. 참가자별 목록 및 전체 도착 순위가 전체 이름의 기준입니다.
- 설정과 경기 기록은 페이지 메모리에만 있습니다. 새로고침하거나 탭을 닫으면 초기화됩니다. 조작 방지 서버나 외부 결과 인증은 없으므로 실제 자산·상금용 시스템이 아닙니다.

## 검증 재실행과 기록

Chrome 및 Playwright가 있는 환경에서 서버를 켜고:

```sh
node tests/browser.mjs
node tests/speed.mjs
node tests/perspective.mjs
node tests/action.mjs
node tests/park-rides.mjs
node tests/winner-recovery.mjs
node tests/focus.mjs
node tests/end-rules.mjs
node scripts/build.mjs
node tests/build-smoke.mjs
# Playwright가 일반 모듈 경로에 없을 때:
PLAYWRIGHT_MODULE_PATH=/absolute/path/to/playwright/index.mjs node tests/browser.mjs
```

`BASE_URL`로 테스트 주소를 변경할 수 있습니다. 임시 브라우저 프로필만 사용하며 외부 요청은 차단합니다. 브라우저 검증은 실제 시간을 따라 공을 굴립니다. 당첨자 강제 주입이나 경기 건너뛰기 경로를 제품 코드에 넣지 않았습니다.

- [놀이공원 개선 세션](evidence/park-20260921/session.md): 18:50 이후 개선과 단계별 실제 검증. 이전 기록은 각 버전의 결과입니다.
- [검증 보고서](evidence/verification.md): 최종 통과·실패·미실행, 실제 성능
- [물리 결과](evidence/physics-results.json): 4맵 × 10시드 × 1/20/60개 = 120경기
- [배속 검증](evidence/speed-results.json): 같은 시드의 1·2·3배속과 경기 중 속도 변경 비교
- [브라우저 결과](evidence/browser-results.json): PC·모바일 흐름, 실제 렌더링 성능
- [원근 3D 검증](evidence/perspective-results.json): 시점 전환, PC·모바일 최대 60개 공·3배속, 같은 브라우저 재현 및 성능
- [명령 기록](evidence/commands.md), [에이전트 세션 로그](evidence/agent-session.md)
- `evidence/*.png`: PC·모바일·4개 맵 시연 화면
- `evidence/*-round.json`: 실제 검증 경기 설정·시드·도착 기록·당첨자
- `evidence/*-trace.zip`: Playwright 화면·DOM·소스 추적
- `evidence/iteration-*`: 과거 실패를 포함한 실제 반복별 로그. 과거 성공을 최종 버전 성공으로 대체하지 않습니다.

실제 휴대전화, Safari/Firefox, 스피커 청취, 전체 접근성 감사, 당첨 확률 균등성은 검증하지 않았습니다. 기본 제공 WebMCP 도구는 지원 브라우저에서만 등록되며, 네이티브 WebMCP 환경 검증은 미실행입니다.

## 기존 작업 보존 및 Git

게임을 외부 웹사이트로 배포하지 않았습니다. GitHub 코드 전송 승인과 웹사이트 공개 배포는 별개로 취급했습니다.
