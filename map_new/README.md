# ATLAS · 주차 내비게이션

파크의 **아틀라스 주차 내비게이션**에서 입장하거나 <http://localhost:5190/map_new/>를 엽니다. 파크 오른쪽 아래 최신 검증 패널과 <http://localhost:5190/reports/map_new/>에서 실행 결과를 확인할 수 있습니다.

```sh
# 저장소 루트에서
python3 -m venv map_new/.runtime/vision-env
map_new/.runtime/vision-env/bin/python -m pip install -r map_new/scripts/requirements-vision.txt
npm run park:dev
npm run verify --prefix map_new
# 변경 감시: 변경이 있을 때 변환·단위·커버리지·빌드·브라우저·골든·라우터 검증
npm run watch --prefix map_new
# 위 검증이 통과하면 map_new와 reports만 커밋·push하려면
npm run watch --prefix map_new -- --checkpoint
```

기존 스테이징 내용이 있으면 자동 커밋을 보류합니다. 강제 push, 자동 reset·stash는 사용하지 않습니다. 다른 프로젝트 변경은 자동 체크포인트 범위에 포함하지 않습니다. `.runtime/heartbeat.json`은 감시 상태이며 PID가 실제 살아 있을 때만 실행 중인 것으로 취급합니다.

**현재 범위:** 실제 장소 45곳·9개 유형·공개 도면 63장 + 별도의 합성 통합 시나리오, 원본 SVG/PNG/JPG/PDF와 해시, 3D 벽체 메시, 의미가 명시된 SVG의 Node/Graph 변환. 보관 도면은 구조선 후보와 한국어·영어 OCR 1,506개를 제공합니다. 원본을 검토한 4장에는 주차 구획 187면, 6장에는 기둥·계단·승강기·문·실·램프 187개를 추가했습니다. 문·안전 출구가 확인되지 않은 도면은 이동 경로를 생성하지 않습니다. 내 도면 가져오기는 SVG/분석 JSON/이미지/PDF 첫 페이지를 처리합니다.

동북권 B2의 차로·코어는 기존 map의 분석가 주석을 재사용합니다. 축척은 추정값입니다. 원본 1800×1350 이미지 중 (550,330)에서 시작하는 1030×830 영역이 3D와 일치하도록 변환합니다. 현재 차량 회전 조건에서 경로가 불가능하면 안내를 중지합니다. 실제 B2에는 확인된 지상 집결지가 없으며 이를 임의 생성하지 않습니다.

**도로 → 진입 → 주차·EV** 버튼에서 통합 시나리오를 열 수 있습니다. 차량과 보행자, 1·3인칭, 재생·일시정지·배속, WASD/방향키, 화재 위치 변경을 제공합니다. 차량은 속도 3.5m/s, 폭 1.9m, 길이 4.6m, 높이 1.8m, 회전반경 5.2m를 기본으로 사용합니다. 제자리 회전을 허용하지 않습니다. 그래프에서 회전 가능한 경로 중 위험 가중 거리가 최소인 경로를 선택하고 원호로 이동합니다. 각 상태에 이전 회전이 차지한 접선 길이를 보존하여 인접 원호가 겹치지 않도록 검사합니다. 구획 내부에서는 별도 전진·후진 조작을 탐색합니다. 보행 속도는 1.3m/s, 화재 시 엘리베이터는 제외합니다.

## 원본과 결과

모든 새 자산은 `map_new/public/sources`, `photos`, `analysis`, `generated`에 저장합니다. `map/` 원본은 변경하지 않습니다.

```sh
node map_new/scripts/acquire.mjs  # 기존 원본 해시 확인·재사용, 공개 사진 복원
node map_new/scripts/convert.mjs  # 원본 → 모델 JSON + 그래프 + 카탈로그
```

`generated/*.json`에는 계획 `plan`과 인덱스 삼각형 메시 `model`이 있습니다. 메시 단위는 m, x는 도면 오른쪽·y는 위·z는 도면 아래 방향입니다. 지리 좌표와의 정합은 별도 메타데이터에 보존합니다. 각 생성물은 원본 SHA-256과 주석 SHA-256을 보존합니다. 원본 PDF와 사진은 공개 접근 가능 자료이며, 별도 자유 재배포 라이선스가 확인되었다는 뜻은 아닙니다. 출처는 카탈로그에 기록합니다.

사진과 외관 화면은 서울시 **너나들이** 페이지의 네이버 지도 좌표 및 같은 페이지의 실제 외관 사진을 사용합니다. 흰색 상부·회색 하부·어두운 기단·노란 입면·검은 난간을 개념 모델에 반영합니다. 실제 OSM 건물 윤곽과 공개 입주표의 4개 주거층을 사용합니다. 실측 BIM이나 사진측량 복원이라고 표시하지 않습니다. 좌표 출처와 사진 해시를 확인할 수 있습니다.

## Google·Kakao 설정

`map_new/.env.example`을 참고해 `map_new/.env.local`에 브라우저 키를 설정하고 서버를 재시작합니다. 키를 Git에 추가하지 마세요.

- `VITE_GOOGLE_MAPS_API_KEY`: Maps JavaScript API
- `VITE_GOOGLE_MAPS_MAP_ID`: vector map ID, 개발 시 `DEMO_MAP_ID`
- `VITE_KAKAO_MAPS_APP_KEY`: Kakao JavaScript key와 허용 웹 도메인

키 미설정 시 좌표 기반 개념 지도와 공개 사진을 표시합니다. **실제 Google 오버레이·Kakao 로드뷰는 키가 제공되지 않아 라이브 검증되지 않았습니다.** [Google WebGLOverlayView](https://developers.google.com/maps/documentation/javascript/webgl/webgl-overlay-view), [Kakao Roadview](https://apis.map.kakao.com/web/sample/basicRoadview/)의 공식 API를 사용합니다.

## 검증 결과

`verify`는 모든 실행에서 단위 테스트, 원본 변환 골든, V8 커버리지, 빌드, Chrome WebGL 기능·스크린샷 골든, 기존 라우터 단위 테스트를 실행합니다. 각 회차는 루트 `reports/report_TIMESTAMP.html`과 `reports/latest.json`·`reports/index.html`에 기록됩니다. 루트 `index.html`의 파크 내 패널은 최신 JSON을 15초마다 조회합니다.

검증은 별도 포트 5196에서 서버를 시작하고 종료합니다. 사용 중인 5190 서버의 상태 파일은 덮어쓰지 않습니다. 골든 갱신은 `npm run test:e2e --prefix map_new -- --update-snapshots`로 명시적으로 수행하고, 이미지 검토 후 업데이트 옵션 없이 재실행합니다.

전체 목표의 미완료 항목은 [요구사항 추적](docs/REQUIREMENTS.md) 및 회차 보고서에 남깁니다. 테스트 통과를 외부 서비스나 실측 시설 검증으로 간주하지 않습니다.

## 너나들이의 실제 도로 연결

너나들이를 선택하면 서울시 공개 1층 배치도의 차량 진입과 주차구역을 표시합니다. 원본 하단의 타입별 조감도를 제외하고 상단 1000×340px 영역을 모델에 맞춥니다. 8,400mm 치수선을 참고한 추정 축척이며 경계·차로 중심선을 분석자가 추적합니다. `data-kind=lane` 선의 교차점과 `target` 원으로 **노드·연결 그래프를 자동 생성**합니다. 도로 자료는 보관된 OSM XML을 `extract-osm.py`로 재생성합니다. OSM 건물 외곽의 두 기준점으로 배치도를 정합하고 실제 신내역로1길 구간에서 진입로를 거쳐 주차구역 앞 차로까지 안내합니다. 주차 완료 조작을 재현한 경로는 아닙니다. 실제 출입 허용과 장애물은 미확인입니다.

파크 개발 서버를 시작하면 변경 감시 검증기도 자동 시작합니다. `ATLAS_AUTO_VERIFY=0`으로 끌 수 있습니다. 별도 수동 감시가 실행 중이면 재사용합니다. `/api/parking-verification`은 실제 PID 생존과 최근 heartbeat로 상태를 제공합니다. 자동 감시는 검증만 수행하며 자동 커밋·push는 위의 `--checkpoint` 옵션으로 지정합니다.

## 장소·도면·공간 표현

주택 21곳, 공동주택 9곳, 상업·업무 6곳, 공공시설 3곳, 공원 2곳, 공영주차장·도서관·문화시설·종교시설 각 1곳입니다. 장소 유형과 이름·주소·층 검색으로 선택합니다. 공원은 서울시 보라매공원·서울숲 안내도의 실제 지도 부분을 표시하며 원문 전체와 범례는 확대해서 확인합니다. 서울숲 자료의 통제구역은 2026-02-27 문서에 기재된 당시 정보이며 현재 운영 상태가 아닙니다.

**공간 표현·도면 정보**에서 바닥·벽·기둥·계단에 콘크리트, 도장, 벽돌, 타일, 에폭시, 아스팔트 재질을 각각 적용합니다. 계단 단·난간, 기둥 안전 띠, 승강기 문, 차량 차체·유리·바퀴·등을 입체로 표시합니다. 높이·단수·재질은 미리보기 가정이고 실측 BIM은 아닙니다. 차량 표시와 OCR 글자, 자동 검출한 주차 구획 후보는 켜고 끌 수 있습니다. 장애인 구획은 파란 바닥·흰 휠체어·파란 안내판으로 표시하며 차량이 표식을 가리지 않습니다.

동북권 B2는 원본 표기 121면 중 확인한 101면과 공간 오브젝트 87개를 모델링했습니다. 작은 표기·미해석 부분을 완성된 구획으로 간주하지 않습니다. 상세 정보에서 모든 주차면·오브젝트의 평면 치수, 가정 높이, 좌표, OCR 원문과 출처를 확인하고 모델 데이터로 내보낼 수 있습니다.

## 공개 기지국과 충전기 후보

[한국방송통신전파진흥원 전파누리](https://spectrummap.kr/gis/mobile_service.do?menuNo=300480)의 공개 **목록 보기 / 엑셀 내보내기**와 같은 조회 경로로 자료를 수집했습니다. 44개 장소 좌표 반경 1km에서 통신사·LTE/5G별 가까운 지상 무선국 8개씩, 장소당 최대 48개를 보관합니다. 중복을 제거한 공개 기록은 1,925개입니다. 행정구역 중심으로만 확인된 좌표도 보관하되 시설의 전파 점수를 계산하지 않습니다. 14곳의 위치는 발행처 네이버 좌표·OSM 시설/공원 좌표가 있고, 실제 주차면이 확인된 너나들이와 동탄 공영주차장에 후보 비교를 제공합니다.

공개 주파수·송신출력·안테나 이득·높이를 사용하고 [ITU-R P.525](https://www.itu.int/rec/R-REC-P.525/en)의 자유공간 손실식에 로그 거리 지수 3, 벽당 6dB, 지하층당 18dB, 주변 환경 15dB를 **비교용 가정**으로 적용합니다. 불확실성 표시는 ±12dB 가정이며 통계적 신뢰구간이 아닙니다. 결과는 광대역 **추정 수신전력**으로, 실측 RSRP·통신 품질·현재 가동 상태를 뜻하지 않습니다. 안테나 방향·지형·실측 보정은 미확인입니다.

통신 점수는 −105~−65dBm을 0~100으로 환산합니다. 차로가 있으면 통신 50%·접근 30%·공간 20%, 차로가 없으면 통신 80%·공간 20%로 비교합니다. 초록 ≥65, 빨강 <40, 중간은 황색, 자료 부족·보호 구역은 회색입니다. 우선 검토 위치는 초록(65점 이상) 후보에서만 선정하며 기준을 충족하지 못하면 대수를 억지로 채우지 않습니다. 이 임계값은 앱의 비교 기준이고 통신사 품질 보증 기준이 아닙니다. 장애인·전용·기존 EV·차단 구획·위험 반경·비교 크기 2.25×4.6m 미만은 일반 설치 후보에서 제외합니다. 크기 기준은 이 앱의 사전 비교 가정이며 법정 주차 기준을 판정하지 않습니다. 전기 용량·배선·최종 설치 허용은 별도 확인이 필요합니다.

```sh
npm run sources --prefix map_new          # 보관된 도면 원본 확인·카탈로그 갱신
npm run sources:places --prefix map_new   # 공개 위치·공원 PDF 확보
npm run sources --prefix map_new          # 확인한 위치를 카탈로그에 반영
npm run sources:radio --prefix map_new    # 공개 기지국 조회·좌표별 캐시
npm run sources:resolution --prefix map_new # 발행처에 공개된 고해상도 원본 확인
npm run sources:ocr --prefix map_new      # macOS Vision, 한국어/영어 로컬 OCR
npm run convert --prefix map_new         # 보관 자료로 재현 가능한 결과 생성
```

OCR 실행에는 macOS Vision과 Swift가 필요합니다. 변환·빌드·열람은 저장된 OCR JSON을 사용하므로 다시 인식하지 않아도 됩니다. OCR은 이미지 원본 해시가 바뀌면 다시 생성해야 합니다. 공개 기지국의 원문 제원·수집일·선택 조건·원본 해시는 `public/sources/radio/`, 화면용 정규화 데이터는 `public/generated/radio-*.json`에 보존합니다. 기본 재수집은 같은 좌표의 보관 자료를 재사용하며 `--refresh`로 명시적으로 갱신합니다.


### 구획 내부 전진·후진 주차

주차 방식에서 **주차면 앞 / 구획 안 자동 / 전진 / 후진**을 선택합니다. 전진 경로가 없으면 자동 모드는 후진과 재정렬을 탐색합니다. 대천항 북측 8번은 기본 차량(1.9 × 4.6m, 회전반경 5.2m)의 후진 입차를 검증했습니다. 좁은 구획은 여러 번 전진·후진할 수 있습니다. 후진 구간은 황색, 기어 전환은 0.8초 정지, 후진 속도는 1.2m/s로 표현합니다. 차량의 앞 방향은 후진할 때도 유지됩니다. 계산은 별도 Worker에서 실행하며 도면·제원을 변경하면 이전 계산을 취소합니다.

차량 본체와 여유 폭으로 벽·기둥·문·위험 영역과 옆 주차면 침범을 검사합니다. 후진 경로는 최대 10cm 간격, 차체 영역은 최대 30cm 간격으로 최종 검사하고, 회전반경을 보존하는 동작만 사용합니다. 원본에서 연결을 확인한 구획에만 제공하며 장애인·전용·차단 구획은 제외합니다. 탐색 상한은 24,000개 상태이므로 경로 미발견은 실제 주차 불가능 판정이 아닙니다. 예시 차량은 실시간 점유가 아니며 실측·현장 통행 허용은 별도 확인 대상입니다.

### 경사로와 층간 이동

[창동 B2](http://localhost:5190/map_new/?site=changdong-b2)는 도면에 보이는 상부 램프 연결부에서 B2 진입부까지 양방향 경사 주행을 제공합니다. 상부 높이 3.3m와 유효 높이 2.4m는 명시적인 가정값이며 상층 전체 평면은 복원하지 않았습니다. 출발 위치는 차체가 확인된 램프 범위 안에 들어오도록 상단 끝에서 안쪽으로 배치했습니다. 차량의 높이·기울기, 원호 회전, 경로의 3D 길이와 경사 제한을 함께 계산합니다. 허용 경사 기본 20%는 사용자가 바꿀 수 있는 비교 설정이며 법정 기준이 아닙니다.

[층간 경사로·후진 주차 시나리오](http://localhost:5190/map_new/?site=multilevel-lab)는 B2 → B1 경사로와 상층 구획 내부 입차를 연결하는 합성 검증 예시입니다. 실제 시설 45곳·원본 63장 집계에는 포함하지 않습니다. 층별 바닥 표시, 수동 주행의 높이 추종과 내보낸 JSON의 층 정보를 지원합니다. 도면을 가져올 때 명시적 SVG 노드·구획·벽의 `data-y`와 `data-floor`, JSON의 `floors` 및 높이 있는 경로를 보존합니다. 높이가 겹쳐 보여도 연결 정보가 없는 층을 자동 연결하지 않습니다.

계단 주황·문 청록·출구 초록·승강기 보라·경사로 파랑으로 구분합니다. 계단 발판과 난간, 문의 문틀·손잡이·여닫는 궤적, 출구 표지판을 표시합니다. 열린 문의 충돌 위치는 표시된 문짝 위치와 같습니다. 열린 각도·마감·단수·높이는 미리보기 가정입니다. 동탄 1층의 계단 출입문 4곳은 원본에 보존한 개구부에 배치했습니다.

### 고해상도 원본과 자동 주차 구획 분석

발행처 페이지가 직접 제공한 `srcset`에서 더 큰 원본 31장을 확보했습니다. 이전 이미지·새 원본의 URL, 크기, SHA-256과 발행처 페이지 해시는 `sources/resolution-upgrades.json`에 보존합니다. 도면 정보 창에서 해상도를 확인할 수 있습니다. 대천항 관공선 통합사무실의 원본 범례를 대조해 실 16곳·기둥 28개·계단 2곳·승강기 1곳도 추가했습니다.

반복 평행선·끝선·추정 치수 비례로 구획 후보 194개를 자동 검출했습니다. 기존 검토 구획과 일치하는 98개는 청색 점선, 나머지는 황색 점선으로 표시합니다. 이 수치는 확인된 187면과 별도로 집계하며, 후보를 경로·충전기 점수에 자동 추가하지 않습니다. 빗금·전용 표시·시설 용도는 원본 검토가 필요합니다. 패턴 점수는 선의 반복·정렬 점수로서 주차면 확률이나 전파 품질이 아닙니다.

이미지·PDF를 가져올 때도 같은 검출기를 사용합니다. 원본 픽셀과 추정 축척, 분석 영역, 후보 치수는 모델 JSON의 `parkingCandidates`에 보존합니다. 도면 구조선·기둥·높이·진입 허용이 모두 자동 확인되었다는 뜻은 아닙니다. OCR 재생성은 성공한 결과만 원자적으로 교체하여, 인식 서비스가 실패하더라도 이전 파일이 삭제되지 않습니다.

대천항 1층 원본에서 일반 주차면 50곳·장애인 2곳을 대조했습니다. 북측·서측 차로의 진입점부터 장애인 구획을 포함한 52면 **앞 차로**까지 차량·보행 경로를 제공합니다. 화면의 주차면을 클릭하거나 목적지에서 선택하고 안내를 시작합니다. 1·3인칭, 재생 속도와 도착 표시를 사용할 수 있습니다. 주차 방식에서 구획 내부 전진·후진 입차를 선택할 수 있으며 차량 제원과 구획 조건에 맞는 경로만 제공합니다.

### 동탄 1층 구역별 주차 길찾기

### 모든 도면의 Python 분할 분석

`npm run sources:analyze --prefix map_new`는 보관된 **63장 전체**를 Python/OpenCV로 분석합니다. `convert`에도 같은 단계가 포함되며 원본·OCR·알고리즘·출력 파일의 해시가 같으면 결과를 재사용합니다. 별도의 Python 환경은 `ATLAS_VISION_PYTHON`으로 지정할 수 있습니다. 분석 환경은 `.runtime/vision-env`에 격리하고 의존성 버전은 `scripts/requirements-vision.txt`에 고정했습니다.

원본을 축소하지 않고 알파를 흰 배경에 합성한 뒤 회색조, 대비 보정, CLAHE, Otsu와 국소 이진화를 적용합니다. 1,024px 타일을 160px 겹쳐 분석하고 원본 좌표로 복원합니다. 수평·수직 연속선과 사선의 굵은 선을 찾고, 겹친 검출을 병합합니다. 작은 OCR 글자 영역은 제외하며 긴 OCR 문단으로 건물 전체를 지우지 않습니다. 병합 시 2px보다 큰 틈은 연결하지 않아 문 개구부가 타일 연결 때문에 닫히지 않도록 합니다. 이 조건은 모든 문이 인식되었다는 의미가 아닙니다.

`public/analysis/도면ID/`에는 `analysis.json`, 보정 흑백 이미지, 이진화 이미지, 검출선 미리보기, 원본 해상도의 타일 PNG가 있습니다. `analysis/index.json`은 도면 전체 현황입니다. `plan.rasterAnalysis`에 원본 해상도·분할 개수·출처 해시·모델 적용 방식을 기록하고 `plan.wallDetection`에 원본 픽셀과 잘린 도면의 미터 좌표를 함께 보존합니다. 자동 구조선 모델에는 2.8m 높이와 추정 축척을 사용합니다. 원본 대조 주석이 있는 도면은 기존 벽·차로를 유지하며 공원 안내도와 단지 배치도는 벽으로 올리지 않습니다. 자동 후보에는 가구·치수선 등이 포함될 수 있으며 진입점·통행 허용·안전 출구를 자동 확정하지 않습니다.

전체 자료를 시각 대조하여 도서당 3장의 안내 문서와 달리·코이노니아 4장의 입체도를 별도로 구분했습니다. 이 7장은 평면도로 벽체 변환하지 않고 원본·흑백·타일로 제공합니다. 유형 판단과 원본 해시는 `sources/drawing-kinds.json`에 보존합니다. 따라서 라이브러리의 63장은 모두 주차장 평면도라는 의미가 아니며, 안내도·배치도·참고 자료를 포함한 공개 이미지 전체 수입니다.

**공간 표현·도면 정보 → 전체 도면 인식 결과**에서 63장을 선택하고 원본 컬러·보정 흑백·이진화·검출선을 비교합니다. 분할 영역을 클릭하거나 목록에서 선택하면 원본 좌표의 조각을 확대할 수 있고 JSON도 내려받습니다. 청색과 황색은 구조선 유형이며 충전기의 초록/빨강 전파 점수와 별개입니다. 브라우저에서 새로 가져온 파일은 기존 클라이언트 분석기를 사용하며 서버의 Python 분석 결과와 구분합니다.

`npm run test:vision --prefix map_new`는 타일의 전체 픽셀 포함, 경계 병합, 문틈 보존, 흐린 색 선·투명 픽셀, OCR 제외, 사선·빈 이미지·안내도 처리를 검사합니다. `verify`에 Python 회귀 검사도 포함합니다. 보고서의 V8 커버리지 수치는 JavaScript 코어 대상으로 Python 커버리지를 합산하지 않습니다. 구현 참고: [OpenCV 이진화](https://docs.opencv.org/4.13.0/d7/d4d/tutorial_py_thresholding.html), [Hough 선 검출](https://docs.opencv.org/4.13.0/d9/db0/tutorial_hough_lines.html).

### 전체 주차 접근 경로와 자동 시작

주차 의미 정보가 확인된 **실제 도면 4장·187면**의 주차면 앞 접근 경로를 제공합니다. 창동 B2 101면, 대천항 52면, 동탄 1층 31면, 너나들이 3면입니다. 장애인·전용 구획도 앞 차로까지 둘러볼 수 있으며 일반 차량의 구획 내부 입차에서는 제외합니다. 주차 정보가 없는 나머지 도면이나 자동 검출 후보에는 차량 경로를 만들지 않습니다. 라이브러리의 **주차장 길찾기 도면** 필터와 경로 패널의 전체 접근 경로 목록으로 확인합니다.

실제 주차 도면을 열면 확인된 진입점에서 각 일반 주차면까지의 유효 경로를 비교해 가장 먼 목적지를 선택하고 안내를 자동 시작합니다. 기본 차량에서 창동 약 152m, 대천항 약 93m, 동탄 약 22m, 너나들이 약 38m입니다. 각 진입점·목적지 쌍의 회전·장애물 조건을 통과한 최단 경로끼리 비교하며 임의 순환 경로를 최대화하지 않습니다. 도면이나 차량 제원을 변경하면 다시 검사합니다. 재설정은 같은 출발 위치에 정지하고, 합성 검증 시나리오는 수동 시작을 유지합니다. 접근 경로 확보는 모든 구획 내부 주차 성공이나 현장 통행 허가를 의미하지 않습니다.

1인칭은 차량 정면과 경사에 고정된 운전석 시점입니다. 후진 중에도 시선은 차량 앞을 유지합니다. 대시보드에 실제 시뮬레이션 속도·D/R/P 기어·남은 거리·좌우 깜빡이를 표시합니다. W/↑·S/↓로 전후진하고 A/←·D/→로 운전자 기준 좌우 조향합니다. 자동 경로의 회전과 수동 조향 시 대시보드 녹색 방향지시등과 외부 차체의 주황색 등화가 같은 주기로 점멸합니다. 키를 놓아도 시선이 초기 방향으로 돌아가지 않습니다.

### 주차면별 출구·출차 경로

주차 경로 목록을 펼치면 4개 실제 주차 도면의 187개 구획 모두에서 `출구까지` 또는 `연결부까지`를 선택할 수 있습니다. 실제 외부 차로·출구 연결은 73개 구획, 도면 경계까지의 연결은 창동 101개와 동탄 동측 13개입니다. 창동 상층과 동탄 층간의 미확보 도면을 외부 출구로 표시하지 않습니다. 동탄 동측 남단은 원본의 횡단 통로까지 차로를 연장해 차체가 도면 끝에서 잘리는 문제를 수정했습니다.

`구획 안에서 출차`는 선택 차량에 맞는 입차 조작을 검증한 뒤 차량 정면을 유지하며 역순으로 나와, 일방통행과 출발 방향을 지키는 출구 경로에 연결합니다. 전진 입차 차량은 후진 출차할 수 있으며 후진 거리·기어 전환 정지를 표시합니다. 장애인·전용 구획과 차량보다 작은 구획은 내부 출차 버튼을 비활성화합니다. 경로 탐색 실패는 실제 주차 불가능 판정이 아니며, 주차면 앞 경로와 내부 조작의 보장 범위를 구분합니다.
