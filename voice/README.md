# TBD 음성 CLI

터미널에서 `헤이 TBD야`라고 부르고 작업을 설명한 다음, `TBD야 시작해줘`라고 말하면 모은 내용을 Codex에 전달합니다. **`--thread`로 기존 Codex CLI 대화에 연결**하거나, 옵션을 생략해 새로운 Codex 작업으로 실행할 수 있습니다.

## 포커스된 Warp 탭에 전달

```sh
cd /Users/jonghokim/Workspace/hackerton/voice
npm run build
npm start -- --cwd /Users/jonghokim/Workspace/hackerton --warp-focus
```

Warp에서 명령을 받을 CLI의 **빈 입력줄**을 클릭하고 `헤이 티비디야` → 작업 내용 → `티비디야 시작해줘` 순서로 말하세요. 시작어를 인식하면 그때 포커스된 Warp 탭·분할 창에 내용을 붙여넣고 Enter를 보냅니다. 고정된 Codex 대화 ID를 사용하지 않으므로 다른 탭을 선택하면 다음 명령은 그 탭에 들어갑니다. Codex에게 작업을 맡기려면 해당 탭에서 Codex CLI를 먼저 실행하세요. 일반 셸 입력줄을 선택한 경우에는 그 셸로 입력됩니다.

macOS **시스템 설정 → 개인정보 보호 및 보안 → 손쉬운 사용 → TBD Speech**를 허용해야 붙여넣기와 Enter를 보낼 수 있습니다. 마이크·음성 인식 권한도 필요합니다. 메뉴 막대를 클릭하면 `모드: 포커스된 Warp CLI에 입력`과 입력 권한 상태를 확인할 수 있습니다. `마이크 준비 완료` 또는 `TBD · 호출 대기`가 나타나면 음성 인식이 켜진 상태입니다.

Warp가 앞에 없거나 권한이 없으면 전송하지 않고 알림을 표시합니다. 붙여넣기와 Enter 사이에 포커스·창 제목·사용자 입력·클립보드가 바뀌면 Enter를 보내지 않으므로, 이때는 Warp 입력줄을 확인하세요. Warp는 탭 정보를 충분히 노출하지 않아 같은 제목의 탭을 프로그램이 바꾸는 경우까지 식별할 수는 없습니다. 전달 중에는 탭을 전환하지 마세요. 전송 성공 알림은 입력 이벤트를 보냈다는 뜻이며, CLI의 작업 완료 여부는 해당 탭에서 확인합니다.

한글과 여러 줄 내용을 붙여넣기 위해 클립보드를 잠시 사용하고 기존 내용을 복원합니다. 그 사이 새로 복사한 내용은 덮어쓰지 않습니다. 기존 입력줄에 내용이 있으면 붙여넣을 내용과 합쳐질 수 있습니다. 실패한 명령은 자동 재전송하지 않습니다. 이 모드에서 TBD를 종료해도 이미 전달한 CLI 작업은 계속됩니다.

`--warp-focus`는 `--thread`, `--model`과 함께 사용할 수 없습니다. `--text --dry-run --warp-focus`로 실제 입력을 보내지 않고 명령 조합을 검사할 수 있습니다.

## 실행

macOS, Node.js 22 이상, Xcode Command Line Tools의 `swiftc`, 로그인된 Codex CLI가 필요합니다. 추가 npm 패키지나 별도 음성 API 키는 필요하지 않습니다.

```sh
cd /Users/jonghokim/Workspace/hackerton/voice
npm run build
npm start -- --cwd /Users/jonghokim/Workspace/hackerton
```

기존에 열어 둔 Codex CLI에 연결하려면 대상 대화의 ID 또는 정확한 이름을 지정하세요. CLI에서 `/rename`으로 알아보기 쉬운 이름을 붙일 수 있습니다.

```sh
npm start -- --cwd /Users/jonghokim/Workspace/hackerton --thread tbd-voice
```

Codex가 도구로 음성 앱을 실행할 때는 `--thread current`를 사용하면 실행한 대화의 `CODEX_THREAD_ID`를 읽어 연결합니다. 여러 CLI 대화를 열어 둔 경우 이전 대화의 ID를 복사해 사용하는 실수를 피할 수 있습니다. 일반 터미널처럼 이 환경 변수가 없으면 대상 ID 또는 이름을 명시해야 합니다. 연결 대상은 실행 로그와 메뉴에 실제 ID로 표시됩니다.

```sh
node src/cli.mjs --cwd /Users/jonghokim/Workspace/hackerton --thread current
```

연결 모드는 설치된 Codex의 `codex queue --thread <대화> --message <내용>`을 사용해 실행어가 확정될 때 기존 대화에 사용자 메시지를 전달합니다. 대상 CLI에서 응답과 작업 진행을 확인할 수 있습니다. CLI가 바쁘면 해당 대화의 큐에 접수됩니다. 입력창의 작성 중인 초안을 타이핑하는 방식은 아닙니다. 메뉴에 연결 대상이 표시되며, 잘못된 대상이나 전달 오류가 발생하면 새 작업으로 우회하지 않고 오류를 표시합니다.

처음 실행하면 macOS의 **마이크와 음성 인식 권한**을 허용하세요. `마이크 준비 완료`가 표시되면 시작할 수 있습니다. 호출어와 실행어는 영어 철자 `TBD` 및 한국어 발음 `티비디`를 인식합니다.

로컬 개발 빌드의 실행 파일이 바뀌면 macOS가 권한을 다시 요청할 수 있습니다. 메뉴가 `준비 중`이면 새로 뜬 `TBD Speech`의 음성 인식 및 마이크 요청을 확인하세요.

Apple 음성 인식에서 실제 관찰된 `Hey TV 디아`처럼 영문·한글이 섞이거나 B/V, 아/야가 바뀐 표기도 처리합니다. 호출어와 시작어 모두 같은 이름 판정을 사용합니다.

시작어가 `DVD 야 시작해줘`로 변환되는 경우도 처리합니다. 이 표기는 정상 호출어로 명령 수집을 시작한 뒤 문장 끝의 실행어에만 적용하며, `헤이 DVD야`로는 호출되지 않습니다.

실행 중에는 **Mac 상단 메뉴 막대에 TBD 상태가 계속 표시**됩니다. 클릭하면 실제 마이크 켜짐/꺼짐과 실행 모드를 확인하고 `TBD 종료`로 프로그램 및 진행 중인 Codex 작업을 중단할 수 있습니다.

메뉴의 **입력 음량** 막대는 마이크 신호에 따라 움직이고, **최근 인식**에는 호출어와 일치하지 않은 문장도 표시됩니다. 음량이 움직이지만 알림이 없다면 최근 인식 문장을 확인하세요. 이 문장은 파일로 저장하지 않습니다.

| 메뉴 막대 | 의미 |
|---|---|
| `TBD · 준비 중` | 권한 요청 또는 초기화 중, 아직 마이크를 듣지 않음 |
| `TBD · 호출 대기` | 마이크 켜짐, “헤이 티비디야”를 기다리는 중 |
| `TBD · 명령 수집` | 마이크 켜짐, 작업 내용을 듣는 중 |
| `TBD · 인식 확인` | 마이크를 잠시 닫고 문장을 확정하거나 다음 인식 세션을 준비하는 중 |
| `TBD · 실행 중` | Codex 작업 수행 중, 마이크 꺼짐 |
| `TBD · 전달 중` | 기존 Codex CLI로 명령 전달 중, 마이크 꺼짐 |
| `TBD · 재연결` | 음성 인식 오류 후 재연결 중, 마이크 꺼짐 |
| `TBD · 시연` | 알림 확인용 모드, 마이크 꺼짐 |

프로그램을 종료하면 메뉴 막대 표시도 사라집니다. 이 앱을 실행하지 않은 상태에서는 음성 인식이 동작하지 않습니다. 자동 시작·로그인 시 실행은 설정하지 않습니다.

음성 모드에서 인식이 확정되면 화면 오른쪽 위에 **3초간 알림**을 표시하고 효과음을 재생합니다. 호출어에는 파란 마이크와 **“TBD · 듣고 있어요” + Tink**, 실행어에는 초록 재생 아이콘과 **“TBD · 명령을 실행합니다” + Glass**가 나타납니다. 시작어를 말했지만 작업 내용이 없으면 주황 안내와 Pop 소리로 알려줍니다. 알림은 별도 권한이 필요 없는 앱 내 팝업이며, 터미널의 키보드 입력이나 클릭을 가로채지 않습니다. 중간 인식 결과와 중복된 최종 결과에는 알림을 반복하지 않습니다.

```text
나: 헤이 티비디야
TBD: 듣고 있습니다. 명령을 말한 뒤 “TBD야 시작해줘”라고 말하세요.
나: voice 폴더의 README에 사용 예시를 추가해줘
나: 테스트도 실행해줘
나: 티비디야 시작해줘
TBD: Codex 실행 중 · /Users/jonghokim/Workspace/hackerton
… Codex의 작업 과정과 결과 …
TBD: “헤이 TBD야”를 기다립니다.
```

각 문장 뒤에 잠시 쉬어 인식 확정과 터미널 출력을 확인하세요. 호출·작업·실행을 한 문장으로 말하는 것도 지원합니다. `--cwd`를 생략하면 CLI를 시작한 폴더가 작업 대상입니다. npm을 사용하는 경우 최초 실행 폴더(`INIT_CWD`)를 사용합니다.

| 말/조작 | 동작 |
|---|---|
| `헤이 TBD야` | 새 명령 수집 시작, 이전 미실행 내용 초기화 |
| 작업 내용 | 여러 문장을 순서대로 수집하고 터미널에 표시 |
| `TBD야 시작해줘` | 내용이 있을 때 한 번 실행 |
| `TBD야 진행해줘` / `TBD야 실행해줘` / `TBD야 작업 시작해줘` | 같은 실행어로 처리 |
| `TBD야 취소해줘` | 수집 중인 내용 폐기 |
| 120초 동안 입력 없음 | 수집 취소 후 호출 대기 |
| `Ctrl+C` | 프로그램 종료, 진행 중인 Codex 프로세스 그룹 종료 |

실행 중에는 마이크 수집을 일시정지하고 새 명령을 받지 않습니다. 실행 성공/실패 후 다시 호출을 기다립니다. 기존 대화 연결 모드에서는 전달이 끝나면 다시 호출을 기다리며, 작업 완료 여부는 대상 CLI에서 확인합니다. 이 모드에서 TBD를 종료해도 이미 전달된 Codex 작업은 계속됩니다. 실패한 작업은 자동 재실행하지 않습니다. 시작어는 문장 끝에서, 취소어는 독립된 문장에서 인식합니다. 명령 내용 자체의 마지막에 시작어를 인용하면 실행어로 처리되므로 피하세요. 명령을 모은 뒤 `헤이 TBD야 작업 시작해줘`라고 다시 불러도 기존 명령을 보존해 전달합니다.

## 실행 전 확인

마이크와 Codex를 사용하지 않고 호출·실행 알림과 효과음만 차례로 확인 (약 6초 후 종료):

```sh
npm start -- --test-feedback
```

효과음만 끄려면 `--no-sound`를 추가하세요. 시스템 출력 음량이 꺼져 있으면 소리가 들리지 않으므로 화면 알림을 확인할 수 있습니다. 텍스트 입력 모드에서는 터미널 메시지만 표시합니다.

음량·인식 원문을 터미널에서 진단:

```sh
npm start -- --dry-run --diagnostics
```

마이크와 스피커 환경을 제외하고 실제 Apple 한국어 인식부터 호출어 판정·알림 표시까지 확인:

```sh
node scripts/diagnose-speech.mjs
```

진단은 macOS Yuna 음성으로 생성한 `.build/wake-test.aiff`를 사용합니다. 음성 인식 권한과 Apple 서비스 연결이 필요할 수 있습니다. 성공 시 `feedback-shown`, `visible: true`를 출력하고 종료 코드 0을 반환합니다. 효과음과 Codex 실행은 끕니다. 사람의 발화와 마이크 입력 품질을 검증하는 검사는 아닙니다.

실제 작업 없이 마이크와 호출 흐름만 확인:

```sh
npm start -- --dry-run
```

마이크 없이 같은 흐름 확인 (한 줄씩 입력):

```sh
npm start -- --text --dry-run
```

`--text`만 사용하면 입력한 내용으로 실제 Codex가 실행됩니다. `--timeout 180`으로 무입력 제한을, `--model 모델명`으로 Codex 모델을 선택할 수 있습니다. 지정하지 않으면 기존 Codex 모델 설정을 사용합니다.

## 음성 처리와 Codex 연결

Swift 도우미는 macOS Speech/AVFoundation으로 한국어 음성을 인식합니다. 중간 인식 결과는 실행하지 않으며, 최종 확정된 문장만 수집합니다. 장시간 대기를 위해 인식 세션을 갱신합니다. 문장 사이 세션 전환에는 짧은 공백이 있을 수 있습니다. Apple 인식 오류가 연속 3회 발생하면 원인을 출력하고 중단합니다.

음성을 파일에 녹음하지 않습니다. 기본 음성 인식은 Apple 서버를 사용할 수 있으므로 네트워크가 필요할 수 있습니다. `--on-device`를 사용하면 기기 내 인식만 허용하고, 해당 Mac에서 한국어 기기 내 인식을 지원하지 않으면 오류를 표시합니다. 대기 중에도 호출어 인식을 위해 마이크를 사용합니다. Apple 음성 인식의 정확도는 환경·발음에 따라 달라집니다.

수집한 문장은 다음 명령의 표준 입력으로 전달합니다. 음성 내용을 셸 코드로 직접 실행하지 않습니다.

```text
codex exec --sandbox workspace-write --skip-git-repo-check --cd <작업 폴더> -
```

위 명령은 새 작업 모드입니다. `--thread` 모드는 기존 대화의 작업 폴더·모델·권한 설정을 사용하며, `codex queue`의 `--message` 인자에 문자열 그대로 전달합니다. 두 모드 모두 셸 문자열을 조합하지 않습니다.

Codex는 지정한 폴더에서 파일 수정과 명령 실행을 수행합니다. 인증·모델·프로젝트 지침은 기존 Codex 설정을 사용하며, 음성 명령은 Codex 서비스로 전달됩니다. 비대화형 실행이므로 권한·네트워크 제한으로 작업을 완료하지 못하면 CLI 출력에서 확인해야 합니다.

## 검증

```sh
npm run check
```

네이티브 빌드·코드 서명 검증 후 모든 자동 테스트를 실행합니다. 빌드 후 `npm test`로 테스트만 반복할 수 있습니다. 호출·명령 수집·시작·취소·무입력 제한·중복 방지·실패 복구, 실제 자식 프로세스로의 UTF-8 전달과 종료, CLI 입력부터 실행까지의 흐름, 네이티브 Speech 프레임워크 로딩 및 macOS 앱 실행·통신·종료를 검사합니다. 앱 실행 검사는 로그인된 macOS 데스크톱 세션에서 실행해야 합니다. 자동 테스트는 Codex를 모사한 자식 프로세스를 사용하며, 실제 계정의 모델 호출이나 사람의 마이크 발음 정확도를 검증하지 않습니다.

알림 검사에서는 실제 macOS 팝업 표시, 키보드 포커스 유지, 효과음 파일 로딩, 무음 설정, 연습 모드 문구, 자동 닫기를 확인합니다. 자동 검사 중에는 효과음을 끕니다.

도우미는 LaunchServices로 독립 실행하며, 임시 비공개 Unix 소켓으로 터미널과 통신합니다. 도우미 실행 파일을 직접 실행하면 호스트 앱의 개인정보 권한으로 판정되어 종료될 수 있으므로 `npm start`를 사용하세요.

권한 거부 시 **시스템 설정 → 개인정보 보호 및 보안 → 마이크 / 음성 인식**에서 `TBD Speech` 또는 실행한 터미널을 허용한 후 다시 실행하세요. `codex --version`, `codex login status`로 Codex 설치와 로그인 상태를 확인할 수 있습니다.
