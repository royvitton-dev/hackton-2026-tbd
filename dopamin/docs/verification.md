# 구현·검증 기록

최대 8회, 동일 장애 3회 반복 시 중단 기준을 적용합니다. 초기 골든 생성은 비교 통과로 계산하지 않고, 화면 검토 후 별도 실행에서 비교합니다.

1. 초기 빌드: JSX fragment 닫힘 누락으로 실패. 해당 한 곳과 사용하지 않는 import, ES2023 타입 설정을 수정.
2. 재빌드와 단위 검사 93개 통과. 문장 커버리지 98.19%, 분기 96.60%. 화면 검사에서 도로 메시 감김 방향을 수정하고 로비 카메라 조정.
3. 첫 브라우저 검사 7개 중 5개 통과. 녹음 프레임 부족과 일시정지 시 0.1초 표시 지연 발견. 모달 뒤 WebGL을 정지하고 녹음 검사를 3.5초로 조정. 정지 이벤트에서 재생 커서와 표시 시간을 즉시 동기화. 글꼴을 로컬로 제공.
4. 실패한 음성 등록·화자 주문 및 전체 레이스·결과·리플레이 검사 2개 모두 통과. 직접 확인한 리플레이 스크린샷에서 정지 중 탐색 시 카메라 보간이 중간에 멈추는 문제를 발견해 카메라도 즉시 이동하도록 수정. 일반 주행 시야를 확대.

최종 검사 결과는 `reports/checks.json`과 HTML 보고서에 기록합니다. 물리 마이크, 실제 화자 인식 정확도, 외부 STT 연결은 자동 검사 범위에 포함되지 않습니다.

5. 화면 골든 기준 3개 생성·육안 검토. 포트 충돌 시 5174 자동 선택 확인. Chrome 실행의 샌드박스 EPERM은 승인된 권한으로 해결.
6. 최종 빌드 및 단위 93개 통과. 골든 3개 통과. 브라우저 1개가 IndexedDB 삭제 완료 전 조회하여 실패. 삭제 완료 UI를 기다리도록 테스트 동기화 수정.
7. 프로덕션 빌드에서 전체 브라우저 7개와 골든 3개 모두 통과. 최종 총 103개 검사 통과, 7회 이내 완료. 동일 원인 3회 반복 없음.

## 영상 참고 그래픽·연출 변경 — 중단 상태

이번 변경은 별도 최대 8회 검증으로 진행했습니다. 최종 완료 상태가 아닙니다.

1. 정적 메시 배치 배열의 TypeScript 타입 오류 수정.
2. 빌드 통과, 기존 단위 92/93 통과. 비행 후 충돌로 바뀐 의도적 완주 결과를 검토하고 충돌 시점·방어 검사와 함께 기준 갱신. 단위 108개 통과.
3. Chrome 샌드박스 실행 문제 해결 후 기존 브라우저 7개 통과. 신규 검사 3개는 공통 슬라이더 값의 비정규 형식(`10.0`)에서 실패해 `10` 형태로 수정. 캡처 검토 중 색상 차체 메시 누락 발견.
4. indexed/non-indexed 메시의 배치를 분리해 차체 복원. 자식 모델의 로컬 좌표 보존과 배치 최적화, 메시 손실 회귀 검사 추가. Float32 오차 4.5e-8에 맞춰 좌표 비교 허용 오차 설정. 리플레이 PNG 전체 버퍼 비교가 멈춰 테스트 중단·해시 비교로 변경.
5. 단위 110/110 통과, 문장 커버리지 98.45%, 분기 96.99%, 함수 97.19%, 라인 100%. PNG 해시 비교에서 정지 화면은 같았으나 되감기 후 동일 시각 화면이 달랐음. Trace의 JPEG 프레임들은 동일했음.
6. PNG를 디코딩한 실제 픽셀을 비교하자 일시정지 전후에도 픽셀 해시 차이가 검출됨. 파일 압축만의 문제는 아니라는 것까지 확인. 최신 빌드는 통과. 동일한 화면 비교 단계에서 세 차례 문제가 이어져 사용자 지시에 따라 추가 수정·검증을 중단.

최신 결과: **빌드 통과, 단위 110개 통과, 신규 브라우저 연출 검사 1개 실패, 최종 골든 8개 미실행.** 이전에 통과한 기존 브라우저 7개는 최종 전체 회귀 통과를 의미하지 않습니다. 기준 이미지에는 최종 렌더링 수정 이전 캡처가 포함되어 있습니다.

정확한 픽셀 차이의 발생 원인은 미확정입니다. 일시정지/되감기의 시뮬레이션·연출 계산에 관한 단위 검사는 통과했습니다. 화면 캡처 합성·렌더링 상태까지 동일해지는지 추가 조사가 필요합니다. 근거 없이 단순 GPU 오차로 단정하지 않습니다.

실패 스크린샷, Playwright trace, 오류 문맥을 `reports/replay-debug/`에 보관했습니다. 재개에 필요한 사용자 입력은 **동일 장애 3회 중단 조건 이후에도 화면 재현성 문제를 계속 조사·수정하라는 지시**입니다. 전체 검증이 통과하기 전까지 완료로 표시하지 않습니다.

## 음향·Nintendo 캐릭터·시상대·커피차·GS 광고 — 추가 검증

작업 중 추가된 요청을 같은 변경에 반영했습니다. 이번 검증에서 이전에 중단한 엄격한 리플레이 픽셀 검사 1개는 재개하지 않았습니다. 검사 코드를 삭제하거나 기준을 완화하지 않았고, 원본 기록은 `docs/graphics-verification.json`과 `reports/replay-debug/`에 보존했습니다.

1. 로비·레이스·결과 음악과 공용 음향 합성기, 음소거 기억·일시정지·마이크 입력 중 정지, Nintendo 두상 8종과 프로필 선택 구현. 단위 146개와 빌드 통과.
2. 실제 Web Audio 출력 검사에서 실드 생성과 공격 방어가 같은 음으로 재생되는 문제 발견. 두 음을 분리하고 RMS·최대 진폭·PCM 해시 검사 추가. 음향 브라우저 2개 통과.
3. 캐릭터 선택 버튼의 이미지 조회가 체크 SVG와 중복되어 실패. 체크를 접근성 트리에서 제외하고 대체 텍스트로 캐릭터 이미지 선택. 시상대의 미사용 import도 제거하여 빌드 통과.
4. 우승 시상대 구현: 실제 1위 트로피 상승, 1·2·3위, 정지·9초 자동 전환·다시 보기. 캐릭터·시상대 브라우저 3개와 관련 기준 이미지 4개 생성. 화면 검토에서 트로피와 제목 겹침 발견.
5. 시상대 문구와 캔버스 영역을 분리. 빌드·단위 146개, 브라우저 12개 통과. 골든 기준 12개를 재생성했으며 이 회차 자체는 독립 비교 통과로 계산하지 않음.
6. 추가 요청에 따라 커피차 제작·줄 서기·웃는 표정·잔 전달·축하 멘트 장면을 삽입. 1–7명 손님에게 모두 전달되는 시간축 검사 추가. 단위 156개·빌드, 시상대/커피차 브라우저 4개 통과. 모바일 8명 화면 육안 검토, 관련 기준 이미지 4개 생성.
7. 추가 요청에 따라 GS차지비·GS그룹·계열사 6개 배너를 모든 트랙에 배치. 커피차 배경 배너와 52G·2026 해커톤 시상대 스폰서·조명 추가. 빌드·단위 156개 통과. 최종 브라우저 14/14 통과. 변경한 골든 기준 14개 생성 및 직접 검토 완료.

실제 출력 검증에 사용한 음악·효과음 WAV는 `reports/audio/`에 저장합니다. 커피차의 음성 검사는 `speechSynthesis.speak`에 전달되는 멘트와 호출 시점을 검사하며, 설치된 TTS 음성의 음질을 자동 평가하지는 않습니다. 화면 골든은 Chrome + SwiftShader 고정 환경에서 비교합니다.

이번 추가 기능 최종 결과: **단위 156/156, 브라우저 14/14, 골든 14/14, 프로덕션 빌드 통과.** 측정한 core/audio 모듈의 문장 98.88%, 분기 97.72%, 함수 96.75%, 라인 100%. 요청한 최대 8회 안에서 추가 기능 검증을 마쳤습니다.

이전 엄격한 리플레이 픽셀 비교 1개는 별도 미해결 상태이므로 **전체 프로젝트 완료 판정은 보류**합니다. 해당 문제를 다시 조사하려면 앞선 동일 장애 3회 중단 이후 재개하라는 사용자 지시가 필요합니다. 원본 실패 테스트와 증거는 그대로 보존했습니다.

## 참고 사진 형태의 스폰서 월 · 맵별 건물 광고

이번 추가 요청은 별도 최대 8회 범위에서 검증합니다. 앞선 기능 검증 기록은 `docs/celebration-verification.json`, 엄격한 리플레이 픽셀 검사 중단 증거는 기존 위치에 보존했습니다.

1. 지정한 연합뉴스 사진을 확인하고 상단 행사명·전체 반복 격자 스폰서 월·흰 시상대·붉은 바닥을 적용. 맵마다 카페·해변 상점·목조 휴게소·도시 건물·설원 산장·에너지 시설에 GS 간판을 부착. 빌드 통과, 단위 160/162 통과. 새 건물 간격 검사에서 해변과 화산의 인접 커브 바깥쪽 광고 건물이 겹침. 원인은 도로만 피하고 이미 배치된 광고 부지를 검사하지 않은 것. 최초 실패 출력은 `reports/unit/sponsor-iteration-1.log`에 보존. 8개 화면 기준 생성 후 트로피의 행사명 가림과 모바일 스폰서 월 잘림도 발견.
2. 기존 광고 건물과도 20 이상 거리를 확보하고 주변 일반 건물·나무의 예약 부지를 유지. 행사명을 트로피 옆으로 이동하고 카메라에 스폰서 월 전체가 들어오도록 조정. 단위 **162/162**, 빌드, 해당 8개 화면 검사 통과. 휴대폰은 전체 벽이 보이지만 여백이 커서 최종 높이를 줄임.
3. 휴대폰 시상대 높이를 580px로 조정하고 최종 빌드·전체 브라우저 회귀 및 골든 기준 생성 진행. 기존 엄격한 픽셀 검사 1개는 중단 상태를 유지하고 제외. 브라우저 기능 **14/14**와 골든 12개 기준 생성까지 통과한 뒤, 커피차 기준 준비 중 개발 서버 HMR 연결이 끊겨 자동 새로고침이 발생함. Trace의 `[vite] server connection lost. Polling for restart...` 직후 `Execution context was destroyed`를 확인. 연결 단절 자체의 원인은 미확정이며 이미지 차이로 인한 실패는 아님. 원본은 `reports/sponsor-debug/`에 보존.

4회차에서 빌드 서버의 커피차·맵 기준 8개 생성이 통과했습니다. 독립 비교 직전 사용자가 회사별 사업 특성을 광고에 표현하도록 추가 요청하여 최종 비교를 추가 구현 뒤로 옮겼습니다.

5. 공식 사업 소개를 확인하고 GS차지비(충전기·전기차), GS그룹(산업 연결), GS칼텍스(주유기·유류·화학), GS리테일(편의점·쇼핑백), GS건설(건물·크레인), GS에너지(전력망·저장·수소), GS EPS(발전소·바이오매스), GS글로벌(지구본·무역선) 광고와 사업 문구 구현. 단위 **162/162**, 빌드 통과. 실제 Chrome Canvas에서 8종 원본 PNG 생성, 콘솔 오류 없음. 원본 확인 후 건물 창문 대비 보완.
