# Wonder Park · Eight Wonders, One Park

현재 파크의 모든 어트랙션 8개와 **실제 기능 시연**을 담은 108초 영상. 1920×1080, 30fps, H.264/AAC 스테레오다. 각 어트랙션은 파크의 실제 3D 모델 소개 2초와 앱 시연 6초로 구성하며, 도파민은 18초, map_new는 24초의 시연을 담는다. 새로 작곡한 합성 음악과 폭죽 효과음을 사용한다.

- 재생: <http://localhost:5190/movie/?film=attractions>
- 파크 극장: <http://localhost:5190/park/>
- 영상: [`output/wonder-park-tour.mp4`](output/wonder-park-tour.mp4)
- 포스터·자막·검증: [`output/tour/`](output/tour/)

| 시간 | 장면 | 실제로 보여주는 기능 |
| --- | --- | --- |
| 0–4초 | Wonder Park 전경 | 작은 별의 전체 파크 |
| 4–24초 | 도파민 범퍼카 | 4–6초 3D 소개, 6–12초 레이싱, 12–17초 우승 시상식·트로피, 17–24초 커피차에서 커피 나누기 |
| 24–32초 | 스타라이트 시네마 | 영화 재생과 챕터 선택을 통한 장면 이동 |
| 32–40초 | 매직 보이스 스테이지 | 실제 Apple Speech 호출어 인식 → 명령 수집 → 시작어 → 실행 전 확인 |
| 40–48초 | EVision 피트 스톱 | 실제 3D 차량 회전, 배터리 투시, 충전 이력 확인 |
| 48–56초 | 아틀라스 설계 연구소 | 공개 원본 도면에서 추정 구조선 3D 모델로 전환·회전 |
| 56–82초 | 아틀라스 주차 내비게이션 | 56–58초 3D 소개, 58–63초 원본 도면 → 3D, 63–71초 주차면까지 주행, 71–77초 충전기 설치 후보 비교, 77–82초 화재 우회 |
| 82–90초 | 럭키 핀볼 어드벤처 | 공의 물리 시뮬레이션, 움직이는 놀이기구, 2배속 재생 |
| 90–98초 | 휴가 거래소 | 12개 봇의 실시간 시장, 지정가 매수, 실제 체결과 잔고 갱신 |
| 98–108초 | GS 폭죽 피날레 | 성에 접근 → GS 발사·형성·반짝임·흩어짐 |

GS는 파크의 `createGSFirework`를 그대로 촬영한다. 100.7초에 솟아오르고, 101.6초부터 금빛 G와 하늘빛 S가 형성되며, 102.7–104.3초에 완성된 글자가 반짝인다. 이후 입자가 흩어져 사라진다.

## 시연과 데이터

브라우저 화면은 실행 중인 앱에서 실제 버튼을 눌러 촬영했다. `assets/tour-demo/*.mp4`는 도파민 18초, map_new 24초, 나머지는 각 6초의 녹화이고, 같은 이름의 JSON에는 조작 전후 실제 상태와 검증 결과가 있다. 도파민의 세 장면은 동일한 실제 경기에서 이어지며, 우승 트로피 상승과 커피가 참가자에게 전달된 상태를 검증한다. 미리보기의 장면 이동 버튼으로 도파민 세 장면과 map_new 네 장면에 바로 접근할 수 있다. 게임은 샘플 참가자, EVision은 앱의 예시 차량 데이터를 사용한다. 설계 연구소의 구조선·축척은 추정치이며 공사 중 표시를 유지한다.

map_new는 신내소행주 너나들이의 공개 도면을 열고 3D 공간을 회전한 뒤, OSM 도로에서 주차 P2 구획 안까지 소형차 예시(1.7 × 4.1m, 회전반경 4.2m)를 실제로 이동시킨다. 도착 좌표가 주차면 중심에서 0.3m 이내인지 검증한다. 현장 실측 전의 모델 경로 미리보기다. 충전기 입지 화면은 공개 기지국 자료에 따른 추정 점수를 비교하며 후보 개수를 3 → 1 → 3으로 바꾸고 P3를 선택한다. 설치된 충전기의 안내나 실측 수신전력으로 표현하지 않는다. 마지막에는 별도의 합성 시험장으로 전환하여 서측 화재를 피해 동측 옥외 집결지로 이동하는 보행 경로를 보여준다. 각 장면 하단에 해당 데이터의 성격을 표시한다.

음성 장면은 macOS Yuna 합성 음성 파일을 실제 Apple Speech와 프로젝트의 VoiceController에 입력해 생성한 `voice-session.json`을 시간순으로 축약한 표시 화면이다. 실제 마이크 녹음이나 Codex·Warp 명령 실행은 하지 않는다. 인식 결과는 수정하지 않고 그대로 표시한다.

거래소는 저장 데이터를 분리한 실제 Rust 엔진과 12개 실제 봇으로 촬영한다. 기존 시장의 주문이나 잔고에 영향을 주지 않는다. UI에서 제출한 주문의 체결과 계정 잔고 증가를 확인하고, 촬영용 프로세스만 종료한다. 성능 벤치마크 영상은 아니다.

## 다시 제작하기

루트에서 `npm run park:dev`로 파크를 띄운다. 다른 주소를 사용하면 `PARK_URL`을 지정한다. Chrome과 ffmpeg가 필요하다.

```sh
npm --prefix movie run tour:stills
npm --prefix movie run tour:render
PARK_URL=http://127.0.0.1:5190 npm --prefix movie run tour:verify
```

기존에 저장한 시연 영상을 재사용하므로 렌더링에는 음성 권한이나 Rust 빌드가 필요하지 않다. 시연도 다시 촬영하려면 다음을 실행한다.

```sh
node movie/scripts/tour-capture.mjs dopamin movie battery_health map map_new pinball
node movie/scripts/tour-voice.mjs
node movie/scripts/tour-capture.mjs trading
```

음성 재촬영에는 macOS의 빌드된 `voice/.build/TBD Speech.app`과 음성 인식 권한이 필요하다. 거래소 재촬영에는 `movie/.movie-runtime/trading-build/debug/leave-engine`에 빌드한 실제 엔진과 설치된 `trading/frontend` 의존성이 필요하다. `CARGO_TARGET_DIR`을 이 임시 빌드 폴더로 설정하고 `cargo build --locked --manifest-path trading/engine/Cargo.toml --bin leave-engine`으로 준비한다.

촬영 시 `/api/park` 목록을 고정하고 모든 ID가 타임라인에 포함되는지 검사한다. 새 어트랙션을 추가할 때는 해당 실제 시연 영상과 기능 설명도 추가해야 한다. 영상 길이는 도입 4초 + 도파민 20초 + map_new 26초 + 나머지 6개 어트랙션당 8초 + 피날레 10초다.

렌더링은 임시 MP4의 프레임 수·해상도·오디오·전체 디코딩을 검증한 뒤 최종 파일을 교체한다. 브라우저에서는 실제 재생, 피날레 탐색, 모든 챕터, 한국어 자막, 모바일 폭, HTTP Range를 확인한다. 파크의 3D 영화관에서도 영상 재생·일시정지·GS 피날레 장면을 검증한다.

기존 30초 제작 영상과 매시간 제작 작업은 별도 경로를 사용하므로 새 투어 영상을 덮어쓰지 않는다. 시네마 장면에 재생한 기존 제작 영상은 프로젝트의 창작 영상이다.
